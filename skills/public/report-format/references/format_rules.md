# 格式化规则

## 四步处理(不改文字内容,只改结构)

### 1. 去源编号残留

源文档的章节编号会随段落一起被抄进来,在报告里毫无意义。

| 输入 | 输出 |
|------|------|
| `11.4.1.1 防雷设计原则` | `防雷设计原则` |
| `6.1概述` | `概述` |
| `1  设计依据` | `设计依据` |

**保留不删:**
- 列表标记: `1）xxx`, `a）xxx`
- 数值: `198 m3/h`, `11000吨`
- 标准号: `GB 50016-2006`
- Markdown 标题行: `## 4.3 供电安全`(以 # 开头的不处理)

### 2. 章节重编号

报告的章节结构由 fire_spec_mapping 定义(如 `## 4.3 供电安全`)。
正文中的子标题(短行)按父节重新编号,带层级:

```
## 4.3 供电安全       ← 父节(由 mapping 定义,不动)

4.3.1 概述            ← 子标题(连续标题 = 父子关系)
4.3.2 设计范围        ← 连续标题 = 同级
设计范围包括...        ← 正文(打破连续)
4.3.3 用电负荷        ← 正文后 = 新同级
4.3.3.1 总用电负荷    ← 连续标题 = 上一层之子
```

层级判断规则:
- 连续两个标题行(中间无正文) = 父→子
- 正文后的标题 = 新同级(回退一层)

### 3. 删空节

只有标题、没有实质内容的 section(只有空行和源标记)整个删除。

```
## 4.5 建筑物通风措施    ← 标题

> 源: 设计说明书 §9      ← 只有源标记,无正文

## 5 消防设施             ← 4.5 被删,直接跳到 5
```

### 4. 生成目录

基于重编号后的标题生成结构化列表,插在报告大标题之后:

```markdown
# XX 消防设计专篇

## 目录

- 1 设计依据及采用的标准
  - 1.1 设计依据
  - 1.2 设计采用的技术标准、规范
- 2 概述
  - 2.1 项目位置
...
```

目录不带页码——markdown 阶段无法知道 Word 分页。导出 Word 后用 Word 自带目录功能重新生成。
