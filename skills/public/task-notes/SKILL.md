# 任务笔记（task-notes）

## 目的

把"属于整个任务但不属于当前这一轮"的信息外化到文件系统：**活跃上下文只放结论和文件路径，原始内容躺在文件里**。上下文压缩（summarization）只保留四段式摘要，笔记是它的文件层搭档——压缩后凭笔记恢复细节。

## 笔记位置与格式

- 路径：`/mnt/user-data/workspace/TASK.md`（按线程持久化，上下文压缩不会碰它）
- 固定四节结构（与上下文压缩摘要同构，两者互相接力）：

```
# 任务笔记：<任务名>（更新于 <日期>）

## 当前目标
正在做什么、验收标准是什么（1-2 句）

## 已做决定
关键决策及理由。用户确认过的偏好/约束用「用户要求：」标注，不可丢失。

## 已完成与改动
已完成的工作、创建/修改/删除的文件与配置、重要工具调用的结论。
只写结论，不写过程；文件路径原样保留。

## 下一步
待办清单、未解决的问题、建议的下一步行动。
```

## 工作流

1. **任务开始**（或用户说"继续"、"接着上次"）：先 `read_file /mnt/user-data/workspace/TASK.md`。存在 → 以它为准恢复状态再开工；不存在 → 首次创建。
2. **增量更新时机**（不要每轮重写全文，只在下列事件发生时更新对应小节）：
   - 用户确认了一个决策、偏好或约束
   - 创建/修改/删除了重要文件、配置、代码
   - 一个阶段完成，得到可用结论
   - 下一步计划发生变化
3. **更新方式**：read → 只改变化的节 → `write_file` 全量写回（文件小，全量写最稳）。
4. **任务完结**：笔记顶部标注 `✅ 已完成 <日期>：<一句话结果>`。新任务另起一份（旧的可改名归档为 `TASK-<主题>.md`）。

## 红线

- 工具调用的原始返回**不进笔记**，只写结论
- 用户明确表达的约束/偏好必须记录并标注「用户要求：」
- 所有工作文件路径原样保留，不得改写或省略
- 笔记是写给"压缩后的自己"看的：写到脱离当前上下文也能照着继续干的程度
- 单轮可完成的简单问答**不建笔记**，避免噪音
