# 投标报价分析技能(只读 · data_source 复用)

## ⛔ 关键规则(必须遵守)

1. **只读不写**:所有工具都是只读查询(`query_dataset` / `query_data_source` 均带只读守卫 + 自动 LIMIT 200)。**绝不执行 INSERT/UPDATE/DELETE/DDL**,也不要建议用户去改投标库。
2. **不触发重计算**:本技能只查已入库的结构化投标数据,不分析投标文件、不跑 OCR、不重算。若用户要"录入新投标",告知"投标库由业务系统维护,本技能只能查"。
3. **建议必须有数据支撑**:给"报价区间建议""自产/外购配比建议"时,必须先取数(构成对比 + 中标率 + 均价),**附样本数**,不要凭空报数。数据不支持就如实说"样本不足,无法给出可靠建议"。
4. **金额单位**:mock 库金额以**元**存储;`winning_price` / `unit_price` / `*_amount` 均为元。报告大额时换算成万元便于阅读,但保留原始精度。
5. **数据范围如实告知**:若查不到(项目/货物未入库),明确说"未找到该投标数据,数据范围有限",**不要退化成网搜**(网搜价格与本系统投标数据无关)。

## 数据来源(背景,无需用户关心)

- 结构化投标数据存于独立库 `mock_market`,经 data_source 连接 `bid-quote` 暴露(只读 MCP)。
- 两张表:`mock_bid`(投标主表:项目/投标方/中标价)与 `mock_bid_item`(分项:货物/单价/**自产金额**/**外购金额**/合计)。
- 当前为**链路演示 mock 数据**(我方=东智装备制造,友商=东方宏业;6 项目 12 标 ~68 分项),真实投标库接入后自动复用同一技能。

## 工作流

### 步骤1:判断能回答
本技能回答**已入库投标数据**范围内的分析。查不到就如实告知(规则 5)。

### 步骤2:调 data_source 工具(直接函数调用,无需 bash)

| 工具 | 何时用 |
|------|--------|
| `query_dataset(source_name="bid-quote", label="<中文 label>")` | **全局聚合**(预置罐装查询,优先用,快且稳) |
| `get_data_source_schema(name="bid-quote")` | 需写自定义 SQL 前,先取表/列字段 |
| `query_data_source(name="bid-quote", params={"sql":"<只读 SELECT>"})` | 按货物/投标方/项目**深挖**(罐装查询不够时) |
| `list_datasets(source_name="bid-quote")` | 兜底:列出所有可用罐装查询的 label 与说明 |

**三个罐装查询(label 精确匹配,直接传中文):**

| label | 用途 |
|-------|------|
| `投标总览` | 投标数 / 我方&友商中标率 / 中标均价 / 时间范围 |
| `货物构成对比(我方vs友商)` | **①核心**:各货物我方自产%/外购% 对比 友商自产%/外购% + 双方均价 |
| `按金额段我方中标率` | 按金额段(<100万/100-500万/500-2000万/≥2000万)我方投标数与中标率 |

**深挖示例(参数化 SQL,仅 SELECT):**
```sql
-- 某货物所有报价明细(我方+友商)
SELECT b.project_name, b.bidder_name, b.won, b.winning_price,
       i.spec, i.unit_price, i.self_amount, i.outsourced_amount, i.total_amount
FROM mock_bid_item i JOIN mock_bid b ON b.bid_id = i.bid_id
WHERE i.goods_name LIKE '%压缩机%' ORDER BY i.unit_price DESC
```

### 步骤3:报告 + 可信度 + 建议

报告数字时附**样本数**(`bid_count` / 货物出现次数)。

**建议层(本技能的核心价值,基于预聚合推理):**
- **报价区间建议**:参考该货物 `competitor_avg_unit_price`(友商均价)与 `ours_avg_unit_price`(我方均价),给"我方报价落在 X–Y 元/单位较有竞争力"的区间;附样本数。
- **自产/外购配比建议**:从 `货物构成对比` 看哪些货物我方 `ours_outsourced_pct` 高(自产短板)、而友商 `competitor_self_pct` 高(对方自产优势)。结合 `按金额段我方中标率` 看短板段(如大项目 0% 中标)→ 建议"提升 X 货物自产率至 Y% / 优化外购供应链以降低大项目成本"。
- 建议**可执行、有数字、有依据**;无数据支撑不报(规则 3)。

### 步骤4:无数据时的兜底
工具查不到 → 告知用户"未找到该投标数据";可用 `get_data_source_schema` 确认库里有哪些表/列,帮用户澄清能问什么。

## 边界:这些不做(转交业务系统)
| 用户请求 | 本技能回应 |
|----------|-----------|
| 录入/修改投标数据 | 投标库由业务系统维护,本技能只读 |
| 生成投标文件/标书 | 非本技能职责 |
| 竞品全市场情报 | 仅覆盖已入库的我方 vs 友商投标,不做网搜 |

## 环境依赖
- data_source MCP 已在 `extensions_config.json` 注册(共享连接,无需单独配置)。
- 仅查询,不依赖任何外部服务运行状态。
