# 报告润色技能（骨架——待实现）

## 设计原则

1. **只改表达，不改技术含义**——数值、标准号、技术参数一个字不动
2. **统一术语**——同一概念用同一个词（如全文统一用"消火栓"而非"消防栓"）
3. **改善流畅度**——修正病句、调整语序、补充必要的连接词
4. **不改结构**——不删节、不加节、不重编号（那是 report-format 的职责）

## 工作流（待实现）

### 第 1 步：读取报告
```
read_file(<报告路径>)
```

### 第 2 步：逐段润色
对每个段落（跳过表格、源标记、标题行）：
1. 修正语法错误
2. 统一术语
3. 改善语句流畅度
4. **不改变技术含义**

### 第 3 步：输出 + 展示
```
write_file(<报告_润色.md>, <润色后内容>)
present_files(filepaths=["<报告_润色.md>"])
```
向用户报告：润色了多少段落、统一了哪些术语。

### 第 4 步：停止
"润色完成。如需进一步调整请告知。"

## ⛔ 不要做的事
- 不要改数值（198 m³/h 就是 198 m³/h）
- 不要改标准号（GB 50016 就是 GB 50016）
- 不要改结构（删节、加节、重编号 = report-format 的职责）
- 不要改技术含义（"丙类"不能改成"乙类"）
