# 条款分类规则(classification.md)

> 依据:设计文档 2026-08-16『详细设计』——分类判据来自本文件(★/"实质性响应"/废标条款字样→mandatory;评分细则表→scoring;其余→normal)。
> 适用:阶段2 子模板①(条款提取)时,Agent 对每条候选条款判 `class`;枚举值域见 `clauses.schema.json`。

## 一、三类定义

| class | 含义 | 失败模式 | 管线行为 |
|---|---|---|---|
| `mandatory` | ★强制条款,**零偏离** | 漏响应/偏离 → 形式评审扣分甚至**废标** | 进偏离表(仅强制+偏离项);商务/技术骨架必填 |
| `scoring` | 打分项 | 静默丢分 | 关联 rubric 项,阶段5 模拟评分逐项找回 |
| `normal` | 普通条款 | 无直接风险 | 骨架占位,正常填写 |

## 二、判据

**M1 —— ★(星号)标记**:条款原文带 ★(或招标文件声明的等价重点标记),且招标文件说明星号条款为不可偏离/必须满足项。
**M2 —— "实质性响应"字样**:条款出现"实质性响应/实质上响应"类表述(如"未实质性响应的投标将被否决")。
**M3 —— 废标条款字样**:条款出现废标/否决/无效标类表述(如"否则其投标将被否决""作废标处理""视为无效投标""不满足即废标")。
**S1 —— 评分细则表**:条款内容来自评分细则表(评分办法章节中的打分表,以 table_id 锚定),即某评分项所考核的具体要求。
**N —— 兜底**:以上判据均不命中 → `normal`。

## 三、判据冲突时的优先级规则

**优先级固定为:`mandatory > scoring > normal`。**理由:两类约束对应两种失败模式(废标 vs 静默丢分),废标风险的代价绝对大于丢分,判据冲突时一律向高风险侧归并。

1. **M 判据与 S1 同时命中**(某条款既带 ★/"实质性响应"/废标字样,又出现在评分细则表中)→ 判 `mandatory`;其评分属性不丢失——对应 rubric 项通过 `linked_clause_ids` 保留与该条款的关联,阶段5 照常对该 rubric 项评分。
2. **M1/M2/M3 之间冲突**:三者同向(都指向 mandatory),不构成真冲突,任一命中即判 `mandatory`。
3. **S1 与 N 的边界**:散文中的打分描述(如"评标委员会可酌情打分")**不构成** S1——S1 只认评分细则表(表格形态、有 table_id 锚点);散文打分描述按 N 判 `normal`,除非同时命中 M 判据。
4. **同一评分细则表多行考核同一要求**:rubric 按行拆成多个 rubric 项;对应条款只保留一条 clause,判 `scoring`,由各 rubric 项的 `linked_clause_ids` 多对一关联。
5. **补遗改变分类**:补遗/答疑把某条款升格为强制(或反之)→ 走阶段3 合并(supersede 流程)更新 `class`;`class` 可人工改,`clause_id` 不变。
6. **拿不准时**:判据无法确定(标记含糊、上下文截断)→ 保守按 `mandatory` 预分类并标 `[待确认]`,进确认门1 由用户裁决——废标风险面前宁可多报不可漏报。

## 四、边界案例

| 案例 | 裁决 | 说明 |
|---|---|---|
| 技术参数表中的 ★ 参数 | `mandatory` | M1;表格内星号同样命中,不限于散文 |
| "商务和技术参数条款必须满足,不能偏离"总述句 | `mandatory` | M2/M3 类表述,整节参数随之按强制对待 |
| 评分细则表内的评分因素描述(如"技术方案先进性 优=8-10") | `scoring` | S1;同时产出 rubric 项,rubric 项 `linked_clause_ids` 回链 |
| 评分办法散文"未尽事宜由评委酌情打分" | `normal` | 规则三.3:散文打分描述不构成 S1 |
| 资格审查条件(营业执照/资质等级) | 按判据判,通常 `mandatory` | 资格不满足=否决投标,常见 M3 表述;`category` 判 `qualification` |
| 签字/盖章/份数/页码/目录类格式义务 | 按判据判,通常 `mandatory` | 常伴"否则废标"字样;同时应在 structure.json 产生 `format_check` 槽进人核清单;`category` 判 `format` |
| 补遗新增"原第 3.2.1 条修改为…" | 旧条款 `superseded_by` 指向新条款 | 新条款重新按判据分类,`from_addendum=true` |

## 五、class 与 category 正交

`class`(mandatory/scoring/normal)回答"违约后果多严重",`category`(technical/commercial/qualification/format/service)回答"条款属于哪个领域"——两个维度独立判定,互不推导。`category` 判据按条款主语:技术参数/技术方案→technical;价格/商务条款→commercial;资质证书→qualification;格式义务→format;服务承诺/售后→service。
