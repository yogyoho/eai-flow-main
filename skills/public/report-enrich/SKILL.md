# 报告扩写技能（骨架——待实现）

## 设计原则

1. **只扩写用户指定的章节**——不做全文扩写
2. **逐段标注**——扩写内容前加 `<!-- ✨ AI扩写，非源文档原文 -->`
3. **不删除原文**——原文保留，扩写内容追加在原文之后
4. **扩写幅度由用户控制**——保守（只补全简略句子）vs 充分（根据规范补充源文档没写的内容）

## 工作流（待实现）

### 第 1 步：读取报告
```
read_file(<报告路径>)
```

### 第 2 步：识别目标章节
根据用户指定的章节号（如 §4.3），定位报告中的对应 section。

### 第 3 步：逐段扩写
对 section 内每个过于简略的段落：
1. 保留原文
2. 根据消防规范常识，补充技术细节
3. 扩写内容前加标注：`<!-- ✨ AI扩写，非源文档原文 -->`

### 第 4 步：输出 + 展示
```
write_file(<报告_扩写.md>, <扩写后内容>)
present_files(filepaths=["<报告_扩写.md>"])
```
向用户报告：扩写了哪些段落、新增了多少内容、哪些是 AI 生成的。

### 第 5 步：停止
"扩写完成，N处标注了AI生成内容，请审核。需要润色(report-polish)吗？"

## ⛔ 不要做的事
- 不要删除原文段落
- 不要不加标注地混入生成内容
- 不要自动链式调用 polish——用户显式触发
- 不要扩写用户没指定的章节
