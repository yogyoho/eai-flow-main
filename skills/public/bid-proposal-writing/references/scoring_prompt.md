# 模拟评分 prompt 模板(scoring_prompt.md)

> 依据:设计文档 2026-08-16『详细设计』阶段5 + SKILL.md 铁律7(评分纪律)。
> 适用范围:**仅 subjective(主观)项**的逐项 LLM 评审。objective 项=确定性状态汇总(基于重灌后的清单状态,不经本模板、不走 LLM);price 项=标"无法模拟"(依赖竞对报价,现库为 mock)。

## 评审纪律(逐项执行,违反任一条即该轮评审作废)

1. **评分办法原文为尺**:只以当前 rubric 项的 `scoring_method` 原文(评分办法原文锚点)为评判标准,不引入任何外部想象的评分标准;尺子本身就是招标文件写的那些分档。
2. **证据 grep 定位**:对回传 md/会话内骨架用 `grep` 检索证据片段,逐项给出 `evidence_quote`;评分办法原文锚点+成稿证据片段两者都必须引用。**无证据的响应按空缺计分,不为留印象给分。**
3. **逐项独立评审(防锚定)**:前项不得影响后项——每次只呈现当前 rubric 项及其证据,不呈现其他项的得分;禁止在理由中引用/类比前项分数;评分从该项证据独立得出。
4. **逐项给分+理由+失分点**:分数必须落在 `scoring_method` 声明的分档内;理由指向具体证据;失分点写清缺了什么内容/差在哪一档。
5. **主观分一律标"模拟参考值"**:本 skill 不承诺与真实评审一致;`score_type=price` 的项一律标"无法模拟",不参评。
6. **改进建议必须落到 rubric_id 与缺失内容**:每条建议指明改进哪个评分项(rubric_id)、补什么内容才能进档,不写空话。
7. 评分输入必须是**重灌后**的成稿状态(score_simulate.py 已把回传 Word 的实际填充重灌进 clauses.json/structure.json);重灌失败标 needs_human_verify 的项既不计 0 分也不静默通过,汇总进评分报告异常区。

## 评审输出记录(逐项一条,交 score_simulate.py 汇总渲染)

```
{
  "rubric_id": "R-005",
  "score": 6,
  "max_score": 10,
  "rationale": "<给分理由:对照 scoring_method 分档,指向具体证据>",
  "evidence_quote": "<成稿中检索到的证据片段;无证据记 null 并按空缺计分>",
  "missing_points": ["<失分点:缺失内容/差距,逐条>"],
  "improvement": "<改进建议:落到本 rubric_id 缺失内容,可操作>"
}
```

- `score` 不得超过 `max_score`,且必须落在 `scoring_method` 的某一分档内。
- 汇总报告由 score_simulate.py 渲染:逐项得分/满分/理由/失分原因 + 改进建议清单(按 失分值×可改性 排序);主观分标注"模拟参考值"。
