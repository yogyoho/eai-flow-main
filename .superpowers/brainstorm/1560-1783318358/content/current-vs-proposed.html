当前架构 vs 你的想法：直接映射线程 outputs/

文档空间"我的文档"的两种数据路径

当前：间接同步路径
1. Agent 写文件
 └─ /outputs/规程.md

2. 前端 POST sync-thread-files
 └─ 时机不可靠（run 结束前触发）

3. sync_thread_files 扫描
 ├─ 全扫 outputs + uploads + workspace
 ├─ 污染（upload 源文件、workspace 脚本）
 └─ 去重（file_ref_path + user_id）

4. 创建 AIDocument（DB）
 ├─ file_ref_path = 物理路径
 ├─ folder_id → Folder 表
 └─ user_id（双 auth 回退）

5. 创建 Folder（DB）
 ├─ name = thread_title（可能 fallback thread_id[:8]）
 └─ parent = 我的文档

6. 前端渲染
 ├─ GET /folders/tree → 文件夹列表
 ├─ GET /documents?folder_id → 文档列表
 └─ 打开文档 → file_ref_path → 读文件

✗ 5层间接：outputs → sync → AIDocument → Folder → 前端树
✗ 同步时机不可靠
✗ 污染（uploads/workspace 误入）
✗ folder 命名靠 thread title
你的想法：直接映射
1. Agent 写文件
 └─ /outputs/规程.md

2. 文档空间直接读取
 ├─ "我的文档" = users/{id}/threads/*/outputs/
 ├─ 文件夹 = 每个线程的 outputs 目录
 ├─ 文档 = outputs 里的文件
 └─ 无需同步、无需 DB、无需等待

3. 前端渲染
 ├─ GET /docmgr/personal-outputs → 线程列表
 └─ GET /artifacts/{thread_id}/{path} → 文件

✓ 0层间接：outputs 即文档空间
✓ 文件写完立即可见（无需同步）
✓ 无污染（只看 outputs）
✓ 文件夹名 = thread display_name
