## Problem Statement（复审取证，距 v1 六小时）

v1 交付后全页复查：任务队列/新建表单/仪表盘卡/消解审核 230 卡/E2E 演练 PASS 均兑现；发现两类新问题：

1. **B1 漏做 5 项**（v1 的 B1 子代理 429 早夭，当日 grep 验证在其完成前执行、结论失效）：DashboardPage:189 副标题开发备忘原文、EntitiesPage:283「重构点」副标题、EntitiesPage:631「TODOS·批量摊销」badge 内联、ReasoningPage:190 DemoTag、ExportPage DemoTag import 残留、ResolutionPanel:822「操作反馈四态」契约表未折叠。
2. **成功带来的新问题**：消解审核待审 230 条，而 `/doc-graph/resolution/pending` 拉取上限 200 且无翻页/搜索——**30 条永不可见**（页面自标「已拉取上限 200」）。人审是当前主线工作流，此为硬阻塞。
3. 小项：任务队列无创建时间列（同名任务难分辨）；证据链引文 quote 全空时显示裸「—」观感差；前端发版后浏览器存留旧 bundle（部署卫生待验证）。

## Premises（沿用 v1 已确认两条 + 复审新增，用户已随方案选择确认）

1. 文案降噪 + 术语别名路线正确，剩余是执行收尾（非方向问题）。
2. 任务 API (b') 产物消费路径已经 E2E 验证，不回头。
3. **消解审核队列容量治理从「可选」升「必要」**——230 条是 force_review 闭环成功的第一批产出，人审可达性是主线。

## Approaches Considered

- **A) 只补文案漏做**：human ~半天 / CC ~40min。✅零风险当天交付；❌30 条待审不可见依旧。
- **B) 文案补漏 + 消解审核可达性** ✅ **已选定**：human ~2 天 / CC ~半天。A 全部 + pending 端点 search/offset + 前端搜索与翻页。
- **C) B + 容量治理全套**（游标分页/批量分批提交/归档视图）：human ~3-4 天。❌230 条是当前峰值，破 500 再上不迟——否决理由同 v1 对深水区的裁决。

## Recommended Approach（B 的任务分解）

### B1 收尾包（纯前端）

1. DashboardPage:189 副标题 →「知识层运营一览：数据沉淀、待审压力、域健康、校验与数据面状态。」（技术来源句删除）
2. EntitiesPage:283 副标题 →「跨域实体检索与状态过滤，支持行级详情抽屉。」
3. EntitiesPage:631「TODOS·批量摊销」内联 badge → 按钮 title
4. ReasoningPage:190 DemoTag 摘除；ExportPage DemoTag import 清理
5. ResolutionPanel 四态契约表 → `<details>` 默认收起 + 摘要行「操作反馈：成功/降级/冲突/在途」
6. 任务队列加**创建时间列**（created_at，MM-DD HH:mm）
7. 引文卡 quote 空 → 显示「（无上下文引文——v1 产物消费路径不含句子级 quote）」
8. 部署卫生验证项：核对 nginx 对 index.html 的缓存头（vite hash bundle 应随 index 更新；若 index 被缓存加 no-cache 一行）

### B2 消解审核可达性（唯一后端触点）

1. **后端** `/doc-graph/resolution/pending` 增 `search`（ILIKE canonical_name，%/_ 剥除）与 `offset` 参数；count 查询同 WHERE 扩展（count 本就存在=真实总数，评审 Issue 1 修正——不新增平行 total 字段）。
2. **前端** 升级既有客户端检索（searchQuery 透传路径，OntologyPage 头部检索框）为服务端 search；「已达拉取上限」改页码翻页（上一页/下一页）；复用既有 count 显示总数（评审 Issue 1/2 修正：无 total 字段新增、无重复搜索框）。
3. **纪律**：pending 端点改动照 v1 eng-review 契约（superadmin→require_permission 现行语义不动，参数 additive）。
