## Problem Statement

用户主诉三轴：①布局/功能设计合理性 ②操作体验（**用户不熟悉英文，大量英文影响操作**）③功能完整性。经全页面 headless 走查（9 页）+ 代码级英文普查 + 已知审计结论对账，定位：

- **英文问题的本质不是「UI 未翻译」**——JSX 文本节点普查仅 5 处英文（Turtle/JSON-LD 等技术 token），页面文案 95% 已中文。真实问题是**开发者词汇渗入操作界面**（见 Premises）。
- **布局非系统性问题**：字号阶梯 14/13/12 已于 2026-10-01 落地（commit c1caea0c9，规范 ui-style-spec.md §9）；剩个位数小毛病。
- **功能完整性主干为真**：图谱浏览（6062 节点/3034 边）、消解审核（四态契约闭环）、推理工作台（24,885 物化三元组/8 规则）、校验中心（国标五项全过）、导出 Turtle（9.7MB）、建模器（真 registry）、实体库（真分页/筛选/抽屉）均接真实数据。**硬断头 = 抽取任务队列是静态示例**（前端 DemoTag，双页自述「待后端任务 API」）→ 管线入口断头 → 消解审核队列恒空（待审实体 0）。

## Demand Evidence

- 用户主动发起全面核查并点名「大量英文影响操作体验」——操作者是真实日常用户（:3010 host dev 实例）。
- 实体库/仪表盘/抽取导入三处 UI 自述「规划中/待后端任务 API/TODOS」——功能缺口是开发者自己标注的，非推测。
- 9-22 三轴完备性判定 P0 五项，四项已解，剩实例级权限（v1 仅 superadmin 可审）。

## Constraints

- `no-core-code-changes`：不碰 deer-flow harness；OntoStudio 是独立服务（FastAPI:8005 + Vite SPA），改动不涉 harness。
- ontostudio 前后端容器均**镜像烘焙无 bind-mount**：改代码必须 `docker compose -p eai-docker -f docker-compose-dev.yaml build <svc> && up -d <svc>`，restart 无效。
- 所有 EAI 定制代码加 EAI-CUSTOM 注释；新代码中文注释。
- 用户偏好「推荐值+理由」、直接实现、反对每任务双评审 ceremony。

## Premises（用户已随方案选择一并确认）

1. 英文修法 = **文案降噪 + 术语中文别名**，不上 i18n 框架。
2. 布局是个位数小修（按钮折行/角标拥挤/空态引导），非系统性重排。
3. 功能完整性第一硬断头 = 抽取任务 API（ingest-page-audit 已指出为唯一解锁点）。

## Approaches Considered

- **A) 快改包（纯前端文案治理+小修）**：human ~2 天 / CC ~3 小时。✅体验主诉全清、零后端风险；❌管线入口断头依旧。
- **B) 快改包 + 抽取任务 API 接通** ✅ **已选定**：human ~4-5 天 / CC ~1 天。A 的全部 + 后端任务 API + 前端接真数据，「导入→抽取→人工审核→入图」闭环成立。
- **C) 全量治理**：human ~1-2 周。B + 快照调度 + 跨域链路启用 + 术语体系。❌跨域链路是数据/匹配率问题非纯代码，强启有低质量链路风险；体验痛点被拖后。深水项单独立项。

## Recommended Approach（B 的任务分解）

### B1 前端文案包（先行，独立可交付）

1. **页面副标题去开发备忘**：实体库「重构点: 旧版为静态示例表…」、抽取导入「真数据块：…」、仪表盘「数字来自 dg_* 聚合…」等 → 改写为操作者视角的功能说明；开发备注移入 `title=` tooltip 或代码注释。
2. **API 元数据降噪**：`GET /ontology/objects/{type}`、`POST /actions/invoke`、`GET /formal/validate`、`pyshacl 0.40 · shacl_graph 参数`、`POST /formal/load·重读 dg_* 全表（行级 force_status）`、`fingerprint 63302dcf` → 从标题/卡片头撤下，收进「技术详情」折叠或 tooltip。
3. **真英文 UI 中文化清单**（~30 处）：`NAMED GRAPH`→派生图、`dry 运行规则`→试运行规则、`Fit View`→适配视图、右栏 `Registry` tab→注册表、`norm` 列头→规范名（去括号注）、实体库角标 badge「规划/TODOS·批量摊销」改为 tooltip。
4. **消解页契约文档外移**：「操作反馈四态」表移入文档中心或面板折叠，页面只留状态图标+人类可读结果。
5. **术语对照表**（轻量：一个常量文件 + hover 别名，非 i18n 框架）：规则名/谓词/域 profile（eia→环评、doc_graph→文档图谱、bid_quote→投标报价）、etype、`graph:derived:*` 等，hover 显示中文别名。
6. **布局小修**：导出页「全量装载（对账）」按钮折行（加 `whitespace-nowrap` 或改文案「全量装载」+副标签）；实体库默认域改 eia（现默认落在空的 doc_graph 域→假空态「该类型暂无实例」）；建模器空画布加引导文案。

### B2 后端抽取任务 API + 前端接真（第二阶段）——eng-review 终裁：产物消费路径

执行路径（2026-10-01 eng-review D10 终裁，外部声音实查证伪移植路径后改道）：**POST /ingest/tasks(sample_id, force_review=true) 落库(queued) → Starlette BackgroundTasks runner（模块级 asyncio.Lock 串行；converter 纯 CPU 段入 asyncio.to_thread）→ 读同库 `kf_samples.outline_json.ontology`（已持久化的抽取产物，eia_samples/service.py:161-167，extensions DB 与 ontostudio 共享）→ converter 组装 ExtractionPayload（mention/document_id 合成，模式照 `ontology/c_ingest/pipeline.py:374`；force_review=true 全量置 pending_review）→ 既有 `ingest_extraction` 装载入图 → 阶段枚举推进 → 前端轮询 2s**。

**为何不走文档直抽（本段推翻此前 D5/4A 移植裁决，明说）**：外部声音实查三连——①`extract_ontology.py` 是 text→dict（:225），「文档→text」在 extract.py 另 ~300 行不在移植范围；②任务引用的源文件在 **gateway 容器文件系统**（kf_samples 真源不在仓库内），ontostudio-backend 只挂 kernel 卷，**worker 打不开引用文件**；③正则置信度 0.80–0.95 全过 0.7 人审门（ingest.py:64），SC2 闭环会被自己的数据链路打败。「直连文档抽取」降级为后续 TODO（见 TODOS）。

1. **契约先行**，5 端点：`POST /ingest/tasks`（新建+触发；同 sample 活动任务 409）、`GET /ingest/tasks`（ORDER BY created_at DESC LIMIT 50）、`GET /ingest/tasks/{id}`（阶段/状态）、`DELETE /ingest/tasks/{id}`（移除；运行中=aborted 标记自然结束）、`GET /ingest/tasks/stats`（置信度分布）。契约草案一并裁决：轮询 2s、模块级 asyncio.Lock 串行、权限门=**require_permission 现行语义**（照 doc_graph/routers.py:4 的 system:access 惯例，非字面 superadmin-only）。
2. **语义四条（eng-review D11-D13+精化终裁）**：**force_review**（任务级 flag，converter 全量置 pending_review——SC2 闭环的支柱）；**重跑=替换**（runner ingest 前按 document_id DELETE 旧 mentions，最新任务=文档真源；dg_mentions 无唯一键，裸重跑必翻倍）；**零命中=completed_empty 终态**（合法空结果非 failed，跳过 ingest）；**启动清扫置于 ensure_tables 同一 try/except**（42P01 no-op，不得破坏 tables_ready 降级语义）。
3. **最小落库**：`ingest_tasks` 模型挂 ontostudio 本地 `Base`（`ensure_tables()` create_all 建表；ontostudio 无 gateway `migrate_db()`，将来对既有表加列才手写幂等 ALTER）。**converter 是显式交付物+独立测试**（mention 合成无法被已取消的奇偶测试覆盖）。
4. **前端 DemoTag→真数据**：IngestPage 任务队列接真（阶段枚举文案）；仪表盘「抽取活动」卡同源转真。
5. **不做的**：文档直抽通道（→TODOS）；文件上传；LLM 离线管线接入；强杀运行中进程。

## Open Questions

- 任务 API 的触发形态：**已裁决为「登记+触发」**——v1 任务入参=已登记文档引用（文件上传通道另批），创建即后台执行既有抽取线，见 B2 执行路径。
- 实例级权限（v1 仅 superadmin 可审）不在本方案内——随人审闭环切片后续批次。
- 「视图自发漂移」疑似 bug 因 headless 会话被并发使用污染未定性——实施前若用户复现，走 /investigate 单独查（AppShell hash 路由逻辑本身核查为干净）。
