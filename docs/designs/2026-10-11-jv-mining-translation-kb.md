## Problem Statement

中外合资铁矿公司需将近几年经营文档（英文/法文；PDF/Word/Excel/PPT/图片）翻译成中文并保存到知识库，支撑每周/每月编写各类报告。文档类型：合同、公司制度、管理规范、经营报告、财务报表、供应链数据。本设计基于 EAI-Flow 现有架构做能力扩展：RAGFlow 知识扩展（KB 管理/上传/检索准入）、eai-flow-ocr 独立 OCR 服务 + MinIO + SHA-256 增量（contract_price v2 已验证）、docmgr 文档管理、writing-project 章节化报告工作流、scheduled_tasks 定时任务、MCP 工具 + Skills + 子代理三层扩展模型。

- 资产先行顺序（用户确认）：术语库/黄金集/不译清单全部**从真实样例抽取**（样例验收闸产出），不做代理语料预研——与 Q5 同构。

## Premises（v4，含盲评、两轮评审与用户补充要点修订）

**术语约定：「三闸门」= ①样例验收闸（客户真实样例解锁实施、产出全部阈值与语言资产）②检索链路闸（hit@k 评测 + OCR 数字准确率）③翻译机检闸（下述三轴+质量档）。「三轴」专指机检闸内部的三个校验轴（术语/数值/结构），两者不是同义词。**

1. **真问题=中文知识资产化**：可检索（原文入库即索引）/ 可溯源（chunk 级 doc_id+page/section+sha 血统）/ 数字不错（见前提 3 扫描件口径与构件 2 数值保护机制）；「翻得像人话」不入机检标准（可读性走黄金集人工盲评，见构件 5）。
2. **分流按内容语义**（叙事 vs 表格数值），**分流判据=样例验证头号待决问题**。一期落地形态=**单条翻译管线 + 打标（narrative/tabular/mixed）+ worker 内预留路由缝（routing seam：按 tag 可插拔处理策略的分支点）**；第二管线（表格数值结构化抽取）在样例验证裁明判据后于二期落地。一期不预设路由规则。
3. **检索与翻译解耦**：原文即刻入库，bge-m3 跨语检索支持中文提问；**原件保真存储于 MinIO，中文人读版一期为 Markdown 交付（版式还原不在一期，OQ6 跟踪）**；法文文档**双份索引**（原文保即时 + 中文版译毕追加保质量，对冲 bge-m3 fr→zh 最弱语对）；**扫描件的「数字不错」是相对 OCR 输出的口径**——OCR 数字准确率入检索链路闸并对原件做人工抽检。语言识别为入库时字段（见构件 4）。
4. **PageIndex 现在不引入、不作 RAGFlow 替代**。其 FinanceBench 98.7%（vs 向量 RAG 50-65%）优势场景=长财务文档精确问答，但生产化证据稀少、检索时 LLM 导航慢且贵；若样例验证后「条款级溯源」成验收痛点，按**单 KB 可选挂载的 MCP 检索工具**增量接入（符合三层能力模型），不换检索底座。
5. **翻译验收=机检三轴 + 质量档**：机检三轴（术语/数值/结构）全绿才可交付；**质量档**区分 draft（机检即交付，默认）与 reviewed（MTPE：人工后编辑→术语终检→定稿，走 review_approved 出边）；可读性/忠实度不在机检范围，由黄金集评估（构件 5）与 MTPE 承载。
6. **翻译模型须可本地化部署**；模型选型=样例日双引擎盲测裁决（构件 5）；一期单主模型，一主一备自动路由二期（OQ5）。

## Approaches Considered

### Approach A: 三闸门最小闭环（盲评 48h 原型的正式化）— 【已选定，D11】
入库主干 + 翻译 worker + 评测夹具（检索+翻译质量）+ 打标 stub + MCP 翻译工具入口。Effort M，Risk Low。验收即代码，样例一到即进验收通道；与 Q4/Q5/Q6 三个选择全部兼容。缺位：批量导入 UI / Excel 结构化抽取 / 版式还原 / docmgr 挂接 / TM 引擎 / MTPE 界面（全部样例验证后叠加或二期）。Completeness 7/10。

### Approach B: contract_price 式独立扩展（完整平台版）— 排为二期
A 的一切 + 独立 extensions/translation 包：翻译任务管理 UI、术语库管理界面、TM 记忆库、批量导入向导 UI、Excel 数值域抽取管线（第二管线本体）、周/月报技能接口预留。Effort L（human ~6-8 周），Risk Medium——Excel 抽取与分流判据在零样例下硬建=盲评点名「流沙打地基」；违背 Q5。

### Approach C: 入库前置 hook 薄路 — 吸收为 A 的 MCP 部分
knowledge create_doc 挂 ingest 钩子 + 翻译暴露为 MCP 工具。Effort S（human ~1-2 周），Risk Low。但机检三轴与术语库无承载点，验收标准落不了地。其 MCP 化思路并入 A。

## Recommended Approach

**方案 A（用户 D11 拍板）**：Q4「先把管线做硬」的最小可验证真子集——每行代码都可被样例验证。B 为样例验证通过后的二期叠加。

### 闸门与轴（消歧）

三闸门：①**样例验收闸**（解锁实施；产出：全部阈值 + 术语库首批内容 + 黄金集句对 + 不译清单 + 模型选型）②**检索链路闸**（hit@5 ≥ 阈值 + OCR 数字准确率抽检达标）③**翻译机检闸**（三轴全绿 + 质量档路由）。三轴=机检闸内部：术语轴（术语库强制替换后命中核对）/ 数值轴（占位符回注 + 注册表对账 + 全文多重集归一化比对）/ 结构轴（block parity diff）。

### 一期构件（全部映射平台现有件）

1. **入库主干**：扩展 knowledge 上传链路（`backend/app/extensions/knowledge/routers.py:408` `POST /{kb_id}/documents`）→ MinIO 存原件（**复用 knowledge/storage.py 的 StorageProvider 抽象，不复制 contract_price storage**（R7/共享代码裁定）；SHA-256 去重拦同文件重复上传）→ 解析（电子件 docx/xlsx/pptx 按 block 树抽取；born-digital PDF 直接解析；扫描件走 eai-flow-ocr，compose:340-353）→ chunk 入 RAGFlow 带 (doc_id, page/section, sha) 血统（**chunk_method/parser 配置一律经既有 `DocumentService._CHUNK_METHOD_TO_PARSER` 映射，禁止裸传内部枚举**——R7/SC-1，learning kb-chunk-method-dual-enum）。**验收动作：中文提问命中 EN/FR chunk。**
   **文档版本（重传即替换）**：同源文档修订重传（SHA 变化）时——旧版本 RAGFlow 文档经既有 `delete_doc` 链路下线（chunk 不再可检索）、旧中文交付物在 MinIO 归档（不删除）、新版本全流程重跑；版本链以 (source_uri, superseded_by) 记录。**在途任务处置（R3-1）**：旧 sha 的 pending/retrying/exceeded 任务取消、running 任务完成当前 block 后中止，产物一律走归档路径不入双语桶，取消任务标 superseded_by。
   **文档删除（R3-3）**：`delete_doc` 级联——中文双份索引 chunk 同链路下线；MinIO 中文交付物按同一「归档不删除」策略；该 sha 的 pending/running 任务取消。
2. **翻译 worker（数值结构性保护 + 调用协议）**：
   - **数字 run 占位符机制覆盖全部 block**：表格单元格与叙述文内嵌数字 run（含 '2024年Q3产量' 的 2024/3）送 LLM 前统一抽取入位置注册表，LLM 输入中数字以占位符替换，输出后按位回注；LLM 只译文字。代价：占位符轻微降低含数字句子的语境理解，接受（数字保真优先）。
   - **术语注入**：每次翻译调用注入当次生效的术语表+不译清单；前块尾部 overlap 上下文一期不做、二期按需加（长文一致性一期靠 block 树重组+术语注入）。
   - **强制结构化输出（用户要点）**：LLM 输出协议=JSON（块 id、译文、不确定标记、低置信片段列表）；不确定标记直接驱动 check_failed 的复核定位与 MTPE 优先级排序。
   - **机检数值轴**：注册表对账（占位符 vs 回注）与全文多重集归一化比对**并行运行**——后者覆盖自由文本残留数字。
   - **分隔符归一（确定性）**：按入库语言字段选约定——fr：空格/句点=分组（删除）、逗号=小数（归一 '.'）；en：逗号=分组（删除）、句点=小数；zh 产出按 en 约定渲染。mixed/无法判定：占位符已保证数字 run 原样回注，比对退化为字符串级相等，**不做启发式猜读**。**数字 run 范围=ASCII 数字序列；CJK 数字（如「三千」）v1 不在抽取与比对范围（R7/SC-6）。**
   - **回译自检（用户要点，定向采样）**：不作全量常开（成本×2）；两个触发点——exceeded 前的定向诊断（失败 block 回译比对定位语义偏移）+ 样例日评测的一部分。
   - **失败链**：主模型 failed 重试链（指数退避 ≤3）尽 → 停留 failed 终态并告警（scheduled_task_errors 既有通道）；备模型自动切换二期（OQ5）。
   - **模型接入层**：模型经平台 config.yaml models 段声明，换模型=改配置不改代码。
3. **任务模型（完整状态机）**：
   `pending → running → check_failed → retrying(≤2，逐轴报错+不确定标记重生成失败 block) → exceeded(人工复核队列) / indexed → delivered`
   - **质量档**（用户 MTPE 要点）：draft（默认：机检全绿即交付）/ reviewed（MTPE 定稿：draft 交付后人工后编辑 → 术语终检 → `review_approved → indexed`（双语索引更新）→ `delivered` 替换）。复核裁决出边：`review_approved → indexed`；`review_rejected → archived`（终态：译文留档不索引，原文索引不受影响）。**`review_rejected` 仅存在于 exceeded 队列（draft 未 delivered 时）（R3-2）**；reviewed 档 delivered 之后的否决走「重传即替换」版本流（撤回草稿中文索引 + 归档 + 重译），不新增状态。
   - `indexed → delivered` 分界事件：中文交付物写入 MinIO 双语桶 + KB 内与原文档互链完成。
   - **基础设施失败**（LLM endpoint 不可达 / block 树抽取失败 / **eai-flow-ocr 端点故障**（R7/SC-3）/ **indexed→delivered 阶段的 MinIO 写入或 RAGFlow 索引失败（幂等键=doc sha，重跑安全）**（R7））→ `failed`（指数退避 ≤3，超限终态+告警）。
   - **SOP（用户要点，文档交付物）**：人机分工写进交付 SOP 文档（AI=初译+一致性检查，人=术语裁决+高风险段审核）；逐段修改痕迹留档一期不做、二期与 TM 种子语料同批建设（OQ9）。
   - **触发流**：ingest 完成自动入队 pending（KB 级开关可关）；worker=gateway 内嵌后台循环轮询 Postgres 队列（**D18 复核维持内嵌**；批量回填观测到 gateway CPU 竞争信号时迁独立容器，~半天成本）；MCP `translate_document`（按需建任务，可指定质量档）/ `translation_status`（进行中=进度；check_failed=逐轴失败+不确定段定位；exceeded=复核入口；failed=基础设施详情）；批量回填走 scheduled_tasks。
   - **重启恢复**：gateway 启动遗留 `running` 重置 `pending` 续跑（状态在 Postgres，幂等键=doc sha+任务版本）。
4. **入库打标与语言识别**：入库生成内容语义 tag（narrative/tabular/mixed，判据待样例裁定）+ 语言（en/fr/zh/mixed）。路由：zh 仅索引跳过翻译；en/fr 进翻译队列；mixed 翻译且双语入库；语言字段同时驱动分隔符归一约定。
5. **评测夹具（检索 + 翻译质量双轨，吸收用户黄金集方法论）**：
   - **检索轨**：脚本+问题模板样例前预建；样例日 smoke 8 条 → 20 条，hit@5 中文命中 EN/FR chunk。
   - **翻译质量轨（黄金集）**：样例日从真实样例抽 **50-100 句对**起步（人工参考译文由客户双语员工提供——调研函第⑤项对应），目标规模 200-500 句随上线扩充；覆盖高频句型/易错术语/长难句（定义条款、免责条款、条件句、长被动、数字密集句）。**三指标**：忠实度（漏译/添译/语义反转，权重最高）/ 术语一致率（术语表自动匹配）/ 可读性（人工盲评，MQM 式错误标注更佳）。**工程指标**：单句延迟、百万字符成本、格式保留率、超长一致性（首尾两段对照）。**A/B 双跑**：2-3 个候选模型同语料并行，记录错误类型分布而非只看总分；**英中/法中分开打分**。
   - **OCR 数字抽检**：样例扫描件人工比对原件 ~1h。
   - 样例验收闸合计约 **1.5-2 天**（可跨两日）：检索 1.5h + 黄金集起步 3-4h + 双跑评测 2h + OCR 抽检 1h + **术语提取与不译清单整理 3-4h（客户双语员工参与，依赖调研函⑤人选）** + **阈值裁定（与客户验收人）1-2h**（R3-4）。
6. **术语库机制（动作三分，吸收用户不译清单）**：yaml 术语库，词条三动作——`force`（强制译文）/ `forbid`（**不译清单**：公司名/品牌/股票代码/法规原文/特定缩写，原样保留）/ `keep`（原文保留）。一期机制+空表起步，**首批内容（300-500 条目标、起步 100-200 条，含法中英中双向，标注词性与领域）= 样例验收闸产出**，从真实合同与财报抽取。
7. **MCP 工具**：translate_document（可指定质量档）/ translation_status 暴露给 agent；**执行走既有 extensions 权限与 owner 过滤（与 knowledge_scope 准入同源）**（R7）。
8. **交付物落点**：中文 Markdown 存 MinIO（双语桶）+ KB 互链；docmgr 挂接一期不做（无服务端建文档 API，OQ7 跟踪）。

### 数据流（R7 补，eng-review 架构节）

```

  ▼
MinIO 原件（StorageProvider，SHA-256）──born-digital──▶ block 树解析（同步段 to_thread）
  │ 扫描件
  ▼
```

### R3-1 — completeness

**Problem**

> 重传即替换 covers the revision case, but a translation task already pending/running/retrying for the old sha when the new version is uploaded has no defined fate: the idempotency key (doc sha + 任务版本) makes it a distinct task that will run to completion and produce a fresh Chinese deliverable for a superseded document, potentially writing into the live bilingual bucket the very content the version rule just archived.

**Remedy**

> Define supersede-time task handling: on re-upload, cancel or reset tasks keyed to the old sha (or force their outputs onto the archive path), stating the disposition for each state it may be in (pending/running/retrying/exceeded).

### R3-2 — completeness

**Problem**

> The reviewed (MTPE) tier delivers the draft first (机检全绿 → indexed 双语索引更新 → delivered), and the next sentence offers 复核裁决出边 with both edges; if review_rejected can fire after the draft is already delivered and dual-indexed, the fate of the draft's already-indexed Chinese chunks is unspecified — archived is defined as 译文留档不索引, but the draft WAS indexed, so retraction is undefined and stale draft content may stay live.

**Remedy**

> State whether review_rejected exists post-delivery; if yes, specify that it retracts the draft's Chinese index entries and archives the replaced deliverable; if no, scope the rejected edge to the exceeded queue only.

### R3-3 — completeness

**Problem**

> Outright document deletion has no lifecycle behavior: the design covers revision (重传即替换) but nothing defines cleanup of the Chinese dual-index chunks, the MinIO Chinese deliverable, and any in-flight translation task when a document is deleted from the KB — the asset-factory promise (lineage, retrievability) leaks stale Chinese assets on delete.

**Remedy**

> Add a deletion rule: delete_doc cascade removes the Chinese dual-index chunks, applies the same archive-or-remove policy to the MinIO deliverable as supersession, and cancels pending/running tasks keyed to that sha.
