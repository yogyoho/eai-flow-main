01

现状诊断

对照截图逐项核对,四个问题均为「视觉层」问题,不动数据与流程即可修复。

P1 · 排序缺陷 附件编号按字符串排序,数字失序

「附件 2」被排到「附件 16」之后,用户按序核对时来回跳跃;树内其余分组同理。

附件 1 → 附件 10 → 附件 11 → … → 附件 16 → 附件 2 → 附件 3
P2 · 信号噪音 处处红点 = 没有红点

16 个叶子全部红点、矩阵每行同一红色「待人工核对」徽章——告警失去了指向性,用户只能逐行读。

「1  1」「16  16」两组数字并排,无法分辨哪个是总数、哪个是待核对数;分组头没有确认进度。

02

要求来源 · 从「树导航」到「筛选面板」

左侧的真实职责只有一个:过滤右侧矩阵。但树形外观(文件夹图标、展开箭头、逐项叶子)会诱导用户把它当成「文档目录」或「待办清单」——控件隐喻与功能语义错位。本节先拆解三类理解偏差,再给出推荐方案与备选,最后附微文案与职责边界清单。

偏差 A · 当成文档目录 「附件 1~16」像文件列表,用户以为要点进去阅读

文件夹图标 + 展开箭头 + 缩进叶子 = 文件管理器的心理模型。用户在此寻找「打开 / 预览」,而实际点击行为是「筛选矩阵」——期望与结果错位,点击后「什么都没打开」,只觉得右侧列表变了。

偏差 B · 当成待办清单 红点逐行排列,像要在此逐条处理的 checklist

确认操作全部在右侧,左侧却呈现「逐项」形态,用户可能试图在左侧逐个「消化」红点、寻找确认入口,或在叶子上右键找操作——而左侧根本没有逐项操作能力。

偏差 C · 一个控件两种行为 点分组 = 筛选,点叶子 = 跳转定位,外观却完全一致

分组行是「过滤」语义,叶子行是「定位」语义,视觉上无法区分,用户无法预测点击结果。这是三类偏差中最伤可用性的一条。

维度 方案 A · 刻面筛选面板 ✓ 推荐 方案 B · chips 并入矩阵头 方案 C · 树形强化
形态平铺筛选选项:来源单选 + 状态多选 + 必答开关取消左栏,来源作为矩阵卡片头的 chips保留树结构,替换图标 / 文案 / hover 动词
消除偏差彻底 — 外观即功能,无目录暗示彻底 — 且矩阵宽度显著增加部分 — 树形外观的「目录暗示」仍在
信息密度进度 + 来源 + 状态一站式进度保留,来源分布概览弱化全部保留
来源增多时好 — 列表自然滚动差 — chips 溢出换行好
改动量中 — 重写左栏渲染,测试微调大 — 合并双栏布局小 — 仅样式与文案
结论推荐:语义对齐最彻底来源 ≤ 5 个时可考虑快速止血 / 过渡方案

方案 A · 刻面筛选面板 推荐

把「树」换成三个显式筛选器:来源(单选)、状态(多选)、必答开关,进度概览独立成块。平铺 + radio/checkbox 形态让「点击 = 筛选」不证自明。标记 ①–⑥ 对应下方注释。

A1进度概览独立成块 — 进度不是筛选器

「核对进度」(三段条 + 22/40 分数 + 图例)置于面板顶部、以卡片与筛选选项隔离。进度回答「还剩多少没核对」,筛选回答「我想看哪些」——两件事 previously 混在树行里,是歧义来源之一。

区块 12px 内边距 · var(--paper) 底与筛选区之间 10px 间隔
A2来源 = 单选刻面 — radio 形态即语义

单选圈(radio)明示「互斥」,选中 = 填充圆点 + 左侧 2.5px 竖条,与矩阵选中行同语言。hover 时计数暂隐、行尾浮现「仅看」动词——把点击结果预告给用户,消除「点了会怎样」的疑虑。告警胶囊仅 blocked>0 时出现,沿用 §02 原方案。

radio 14px · 选中内圆 6px计数 tabular-nums 右对齐
A3状态 = 多选刻面 — 筛选逻辑单点化

checkbox 承接「可组合」语义:待核对 / 草案 / 已确认多选叠加,★必答作为第四个快捷开关。状态筛选从矩阵头部 chips 收编至此(§03 B2 相应简化),所有筛选维度集中在左面板一处,矩阵头部只留进度与搜索。

checkbox 14px · 选中 brand 底白勾多选交集: AND 语义
A4筛选状态外显 — 反馈出现在结果旁边

已选筛选以可移除 chips 列在面板顶部(× 单独撤销),右侧「显示 16 / 40」实时计数;同一组 chips 镜像到矩阵卡片头,让「列表为什么变短」永远有答案。这是过滤器设计的第一原则:状态可见、可撤销、有计数。

chips 镜像至矩阵头计数格式「显示 N / M」
A5定位职责移交搜索 — 摘除「叶子跳转」歧义

原「点叶子滚动到矩阵行」是导航行为,与筛选混在同一控件里,是偏差 C 的根源,予以摘除。定位具体条款改由搜索承担:输入「附件 12」回车即命中并高亮矩阵行;矩阵行点击选中保留。左面板从此只做一件事:筛选。

搜索命中 = 滚动定位 + 行高亮命中计数显示于搜索框尾
A6清除筛选常驻 + 空态引导

「清除全部筛选」常驻底栏,处于筛选态时高亮;筛选组合无结果时,矩阵空态文案给出「清除筛选」按钮,不留给用户死胡同。卡片标题由「要求来源」改为「筛选 · 来源与状态」,Badge「来源导航」改为「点选即筛选」。

空态: title + description + 清除按钮复用现有 EmptyState 组件

方案 B · 取消左栏,来源 chips 并入矩阵头 来源 ≤ 5 时可考虑

最激进的方案:筛选就地化,双栏变单栏,表格宽度显著增加。来源数量少时体验极佳,但来源分布概览消失、chips 会随来源增多而溢出。

原则一个控件只承担一种交互语义

四层职责互斥且完整:筛选、定位、选中、溯源各归其位。判断标准很简单——用户看到任何控件,能在 1 秒内说出「点它会发生什么」。凡是需要 tooltip 或试错才能预知行为的控件,都是隐喻错位的候选。
