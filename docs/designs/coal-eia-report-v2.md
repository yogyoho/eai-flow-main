## 问题与目标

`skills/public/coal-eia-report/` 现为纯提示词技能（prompt + 5 个旁路 calc 脚本 + 10 份静态参考 md），与已升级为管线技能的 `geological-report` v2 相比缺整个机器层：

| 能力 | geological-report v2（参照） | coal-eia-report 现状 |
|---|---|---|
| 数字防护 | `{{SLOT:key}}`/`{{TABLE:族}}` 槽位注入，数字零过 LLM | LLM 直接写数字（仅 `[XX]` 占位约定） |
| 数据层 | ingest.py 唯一写者 + 表单 schema + 门1 完备性 | 对话实体卡片（散文，会话断即丢） |
| 计算 | formula_runner 冻结 + trace + impacted 改参反查 | 5 个 calc 脚本旁路，结果手抄进正文 |
| 状态/续跑 | progress.py 状态机 + SHA-256 快照 | 无，断线即丢进度 |
| 跨章一致性 | 25 合约五类（XS/FC/CC/NR/SL） | 无（仅实体泄漏扫描） |
| 派发 | 控制器 + batch_task 子代理 + 波间要点包 | 单上下文逐章写（700 页写不动） |
| 范文 | samples_bank 切片库 + bank_index | 4 个 chapter_examples markdown |
| 结构源 | references/stages/*.json 机器可读 | KF 模板或静态 markdown——**report_structure.md 已被横城实体污染**（白芨滩/太中银/明长城/宝丰光伏硬编码进"通用"模板） |

**规模约束（用户 2026-09-06 补充）**：地质报告约 150 页，环评报告约 **700 页**——文档空间编辑器对大文档加载性能低，报告必须切分到小文档粒度（见 D9）。样例实测：192–337 张表/部，最高 91% 段落位于表格内——数字主体在表格，纯 LLM 生成必然失控。

目标：原地升级为「数据表单 + 冻结计算 + 确认门 + 分层派章 + 跨章一致性合约 + 快照续跑 + 双通道交付」的管线技能，按多场景语料建 stage 矩阵。



- 节 VERIFIED 唯一通道 = 所属章 `build_output --chapter` 单章门 rc=0（批量 `progress.py gate` 自动回写；手动 mark 禁用，沿 geo bug-3049）
