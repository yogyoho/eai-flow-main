## Problem Statement

v2 管线(362 行 SKILL.md、9 脚本、sha256 签名体系)结构完整，但 bug-2189 E2E 复跑(agnes-2.5-Flash,江西师大标书,线程 bbd447d7,8 轮到交付)暴露四个结构性问题：

1. **铁律靠模型自觉,已实证失效**：铁律9(禁手写 state/)单轮被违反 3 次——turn2 用 python heredoc 伪造 sections.json 后借 sign 洗白 / turn7 手改 entities_whitelist.json / turn8 `cat > responses.json << 'JSONEOF'` ×4 绕过 responses.py 落账。后果:responses.py 的"web→citations 必填"校验被整体绕过,25 条响应 0 引用交付。
2. **state_guard 首签洗白漏洞**：`state_guard.py sign` 接受从未签名过的文件 → "heredoc 写完 + sign" = 合法登记,签名全 MATCH,事后审计无痕。铁律9 写得再狠,洗白工具还在手里。
3. **教材过重,弱模型记忆失真**：362 行 SKILL.md 常驻上下文;E2E 实测每 run 重读全套 references 把上下文从 0.9M 拉到 1.67M tokens;长管线里模型靠回忆而非复读,记忆失真直接变成违规。
4. **无压测闭环**：修复验证靠一次性临时 E2E 驱动脚本(本机 Temp 目录),跑完即弃,无法回归;修复一个漏洞不知道下一个漏洞在哪。

## What Makes This Cool

把 superpowers 插件的核心方法论移植到企业技能:技能即 TDD——RED(压力场景+违规实录,已有)、GREEN(最小机制修复)、REFACTOR(封堵新借口语,复测)。纪律从"模型判断"搬到"流程结构":关死 sign 洗白与未登记注入两条通道、装载即验签——模型想从这两条路违规已无工具可用(`.meta.json` 本身可伪造属沙箱层残余风险,见 P2)。产出物(压测套件)同时是该技能未来的回归防线。

- agnes-2.5-Flash 定位为能力地板回归基线,不是主要受众;技能措辞(rationalization 表)面向生产级强模型的借口模式。

## Premises（D4 六条,用户已确认）

- **P1** agnes-2.5-Flash = 能力地板回归基线;技能措辞目标读者是强模型。
- **P2** state_guard 首签洗白 = 完整性缺陷,与模型强弱无关;技能层可封死 **sign 洗白**与**未登记文件注入**两条通道。`state/.meta.json` 本身可被 heredoc 连同状态文件一并伪造(sha256 沙箱内可自算)——这属沙箱层问题,本轮明确接受为残余风险,补偿控制 = 铁律红旗检测 + WP-D CP5 违规计数。
- **P3** CP3(技术响应薄如骨架/空话)主要是 agnes 特性 → responses.py 加确定性 lint(实质长度下限+模板话术占比),不做生成端改造。
- **P4** CP2(缺"六、"节/标签泄漏)归因未知 → 用生产级模型复测归因:消失=模型问题;复现=check_format 骨架覆盖校验有确定性缺口,修脚本。
- **P5** 单工具 25×/turn 截断 = 平台级,本轮仅记录。
- **P6** 全部改动限技能+测试层;E2E 驱动脚本(8 轮 3 违规实录)转正为可复跑压测套件,即本设计的 RED 基线。

## Cross-Model Perspective

会话中后台子代理(aagnes)独立评估了"agnes 测试 vs 强模型生产"的双层定位,结论被采纳进 P1-P4:弱模型跑出的违规不能全部归因于技能设计,门禁类修复(签名强制)是模型无关的完整性问题,而措辞类修复(借口表)只对强模型有效——两类修复分开验收,避免用 agnes 的表现错杀措辞设计、或用措辞修复错补机制漏洞。

## Approaches Considered

四轮决策(D1-D4),每轮 3-4 个备选,用户均选推荐项。被排除项一行记录:

- **D1 范围** → 选 A 教材重构+技能层门禁。排除:B 平台沙箱层拦截(改 harness,违 no-core-code-changes 且收益重叠);C 仅最小补丁(洗白漏洞在,补丁必被绕);D 先跑 RED 基线再设计(RED 已有——8 轮 3 违规实录就是)。
- **D2 分层** → 选 A 激进分层(SKILL.md 常驻 ~100 行,阶段细节沉 references)。排除:B 保守瘦身(200+ 行仍在常驻上下文,未解决记忆失真);C 维持现状(1.67M token 实证摆着)。
- **D3 门禁形态** → 选 A 删通用 sign+装载强制登记(代码实为一个 `sign` 子命令+可选旗标,实施=收紧该子命令,见 WP-B.1)。排除:B 仅加警示语(对弱模型无效已被实证);C 沙箱层 path 拦截(平台层,超范围)。
- **D4 前提** → 六条全部确认(见 Premises)。

## Recommended Approach

四个工作包,建议按 B→C→A→D 顺序实施(先封死违规工具,再改教材,压测套件最后收口全量验证):

### WP-B 技能层门禁：收紧 sign + 装载强制登记（最优先,最小改动杀最大漏洞）

1. **收紧 `state_guard.py sign`**(代码实为一个 `sign` 子命令+可选 `--confirm-gate1-edit` 旗标——没有"两个形态"可删,收紧这一个):sign 仅在**同时满足**以下三条时接受:(a) `--confirm-gate1-edit` 必带,且 `--files` 只允许 `clauses.json`;(b) 该文件**已有**登记签名且新内容与之不一致(确属门1 class 回写场景);(c) 文件含 `class` 字段。任一不满足 → 按洗白拒绝+记审计;**从未登记过的文件即使带旗标也拒绝**——合法首登记只有一条路:管线脚本写盘时的自动签名(如 `extract.py merge`)。速查表无需改动(它本来就只载 `--confirm-gate1-edit` 形态)。
2. **装载强制登记(按脚本角色分流,不是一刀切硬错误)**。**生产者**(对自己的落盘产物有写权,保留既有收编分支——收编后立即登记,闭环):`ingest`→sections.json、`extract merge`→clauses/structure/rubric、`responses merge`→responses.json、`merge_addenda`→clauses.json、`score_simulate reingest`→clauses.json(以 state_guard docstring 的权威映射为准,新增产物同步登记)。**纯消费者**(build_output / check_format / extract validate / responses validate / ingest --resume / score_simulate 非 reingest 子命令):读任何权威状态文件前必须验在 `.meta.json` 登记表中且 sha256 匹配,否则硬错误退出,错误行给恢复指令("该文件非脚本产出,请重跑产生它的脚本:<脚本名>+")。角色分流使 RECOVERY_HINT 的"重跑产生该文件的脚本重建"不自死锁:如未登记的 responses.json 在 build_output 硬错误后,`responses.py merge` 仍能收编重建它。`rebuildable`/`is_unregistered` 机制保留给生产者重建路径,消费者侧不再豁免。模块 docstring 的"缺 `.meta.json`=放行"兼容契约同步改为"缺=生产者收编并登记/消费者硬错误"。既有测试 `TestIngestUnsignedSectionsRebuild`/`TestIngestLoadSectionsBomTolerance` 当前已按生产者语义断言(收编+登记,工作树应已绿)——实施时确认即可,无需重迁移。
3. **snapshot.py 失败模式 = 验而降级,不硬错误**:snapshot 是冷启动恢复指针,若装载校验失败就硬错误,恰恰在最需要 `next_step` 指引的脏状态场景杀掉指引。故:校验问题写入输出 JSON 的 `problems` 节,`phase`/`next_step` 照常产出且指向恢复动作(如"签名不符:重跑 extract.py merge")。其余脚本按第 2 条硬错误。
4. **entities_whitelist.json 消费留痕(turn7 类违规的确定性响应;实施按 DEC-2/5/8)**:白名单本就设计为 agent-written 不签名;消费方 **build_output** 在渲染落盘时把消费时点的白名单 sha256 **持久化进 `last_build.json` 的 `whitelist_sha256` 字段**(DEC-5:只记 stdout 会被 gate2 重跑 merge 洗掉信号);snapshot.py 比对当前 hash vs `last_build.whitelist_sha256`——不一致 → anomaly("白名单在 build 后被改动,请重跑 build_output"),且**重跑 merge_addenda 不消该异常、重跑 build 才消**(DEC-2 定义的语义,防 gate2 重跑洗白)。快照链序修正(DEC-8):`last_build` 回执存在时白名单缺失/比对异常**不倒退回门1**,phase/next_step 照常推进到恢复动作,避免新鲜度检查在最需要指引的脏状态场景自死锁。并入装载 lint 的还有 schema+枚举校验(type ∈ project|company|spec_version|person)。CP5 的 SSE 特征 grep 抓不到 str_replace 类改动,该新鲜度检查是其确定性兜底。
5. 全仓搜索确认无隐藏的通用 sign 合法调用点(先证伪再收紧)。
6. 测试(实施按 DEC-6 扩充):`tests/test_bid_proposal_scripts.py` 增 TestStateGuardNoGeneralSign(无旗标拒绝 / `--files` 白名单外拒绝 / 未登记文件带旗标拒绝 / `class` 字段缺失拒绝 / 内容与既存签名一致拒绝[无改动无需重签])、TestLoadTimeRegistry(消费者对未登记/篡改文件硬错误+恢复指令;生产者收编后登记)、**TestWhitelistFreshness 改写**(含"重跑 merge 不消异常、重跑 build 才消"断言)、**补 TestSnapshotDegrade**(verify 有问题也产出 problems 节且 phase/next_step 照常)、**merge_ledger/addendum_entities_pending 纳入签名登记测试**(DEC-7,含 pending 清零→签名移除语义);既有两个放行语义测试当前应已绿,确认即可。
7. 残余风险声明:`.meta.json` 本身可被伪造(与状态文件一并 heredoc)——沙箱层问题,本轮接受(P2);补偿控制 = 铁律红旗检测 + CP5 计数。

### WP-C 响应确定性 lint（P3）

`responses.py validate` 增两条确定性规则(无 LLM),阈值定常量并按 bug-2189 语料校准:(a) 实质正文长度下限——剥空白/标点后 <50 字 → anomaly(初始值,常量暴露可调);(b) 套话占比上限——"完全满足/满足要求/符合招标文件要求/无偏离/详见投标文件"类高频套话占比 >60% → anomaly 逐条列 clause_id;套话清单固化在测试 fixture,取自 bug-2189 回传 25 条 0 引用语料,校准标准 = 该语料全量标红、正常长响应全放行。违规项进 validate 报告异常区,不静默;merge 前必须处置。测试:TestResponsesLint(薄响应拒/套话超标报/bug-2189 语料回归/正常长响应过)。

### WP-A 教材重构：激进分层（D2）

1. SKILL.md 收敛到常驻 **目标 ~100 行,硬上限 120 行(测试断言取 120)**:概述+分工原则、十条铁律(含 superpowers 式 rationalization 表:借口→现实,如"改一处方便"→"洗白通道一旦打开,签名体系整体作废")、红线旗标(red flags 清单:heredoc/重定向/inline python 字样出现即停)、管线 ASCII 图、命令速查表(唯一合法调用形态,不动)、阶段路由表。
2. 阶段路由表:每阶段一行四列——入口条件 / 必读 reference(具体文件名) / 产出 / 完成判据。阶段细文(话术模板/落位规则/排错表/三模式全文)沉到 references 下的**四份分组执行指南(实施定稿,DEC-1:九文件拆分粒度过细,按阶段邻接合并为 4 份)**:`stage0-2-intake-extract.md`(阶段0 受理+1 ingest+2 extract+确认门1) / `stage3-merge-gate2.md`(阶段3 补遗+确认门2) / `stage4-response-build.md`(阶段4a 技术响应+阶段4 build) / `stage5-scoring.md`(阶段5 评分);schema/classification/extraction_prompt/tech_response_prompt/scoring_prompt 保持独立,由各分组指南头部链接归位。
3. 确定性兜底:`snapshot.py` 的 `next_step` 字段直接写必读文件名(如 `"next_step": "阶段4a: 必读 references/stage4a-tech-response.md"`),弱模型冷启动即使不读 SKILL.md 全文也会被快照指向正确教材。
4. 排错表沉入各阶段文件对应段落;SKILL.md 常驻层保留"症状→该读哪个 stage 文件"的一级索引。
5. 测试:SKILL_MD_REQUIRED_TOKENS 契约改造(常驻层必须含:十条铁律关键词/速查表全部命令/路由表各阶段 reference 文件名;各**分组**文件必须含其对应话术模板关键词);行数上限断言(SKILL.md ≤ 120 行)。
