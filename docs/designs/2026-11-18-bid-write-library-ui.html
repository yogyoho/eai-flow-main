资质素材库
页面功能梳理 × 重设计原型

资质素材库是 owner 级企业资产:资质、业绩、人员、产能、网点、历史标书六类实体, 跨写作任务共用,是「②素材核对」缺口补录的落地页。本稿先梳理现状功能与不变式边界, 再给出补齐字段编辑、佐证管理、搜索与统计概览的重设计原型。

01

功能梳理

页面职责一句话:维护企业可复用的资质事实,让每条投标要求都能落到「有据可查的实体」上。 佐证与绑定的裁决权在断言执行与导出门禁,本页只负责把实体和证据准备到位。

△现状缺口 → 原型补齐项

① fields 无编辑 UI(字段数列只读,实体只有名字没有事实);② 无搜索;③ evidence_refs 无管理入口(佐证只能靠后端,页面上无法补);④ 删除无确认;⑤ 无佐证率概览;⑥ 快速添加与列表割裂。原型 §02–§03 逐项补齐。

无引用实体导出时被 D0 门禁拦截——在佐证抽屉补 evidence_refs 后,以断言判定为准,本页不做人工「已绑定」标记。

1概览条 — 佐证率进入第一屏

实体总数 / 有引用(佐证率)/ 无引用(导出将被拦)/ 字段完整度。佐证率是本页最关键的资产健康度:「有 42 个实体」不代表「能过门禁」,74% 的佐证率才是真相。

2类型导航 rail — 计数 + 佐证率 + 无引用角标

替代原 seg tab:每类一行,图标 + 计数 + 佐证率迷你条,无引用实体 >0 时显示红色角标。带 ?type= 缺口跳转时对应项自动选中,补录上下文不丢。

3搜索 + 佐证过滤 chips

搜索覆盖名称与字段值(找「CN2024-0881」这类证书编号是高频操作);佐证三态过滤(全部 / 有引用 / 无引用)直接服务「导出前清欠」工作流:一次过滤出 11 条无引用逐个补证。

4实体行 = 名字 + 关键字段键值

原表格只有「名称 + 字段数」,用户必须点开才知道实体里有什么。原型把字段键值直接铺在名称下方(mono 小 chip),资质的证书编号 / 有效期、业绩的合同额 / 验收时间一屏可比。

5佐证列:有引用带数量,无引用琥珀警示

沿用外框徽标语言:绿 ✓ 有引用 N 条 / 琥珀 ⚠ 无引用。无引用不是错误而是待办——点击直达该实体的佐证编辑(§03 抽屉),与导出门禁口径一致。

6删除带确认,编辑进抽屉

删除是破坏性操作且实体可能被任务引用,需确认弹层明示影响;编辑统一走 §03 抽屉(名称 / 字段 / 佐证一起管),不再有无字段的「半截实体」。

03

新建 / 编辑抽屉 + 字段模板

补齐现状最大缺口:fields 编辑与佐证管理。抽屉按类型载入字段模板(模板来自后端 contracts.py 的字段语义),字段行可增删;佐证引用(evidence_refs)直接在抽屉内补。

7与 ② 素材核对的闭环

缺口行「无对应素材 → 去资质素材库补录」仍带 ?type= 跳转(rail 自动选中);补录实体后回到素材核对,绑定以断言判定为准——本页始终不越权标记绑定。

04

落地说明

改动集中在 LibraryView.tsx + bid-write.css;API 契约零变更——字段模板是前端引导层,新建仍可只传 name(向后兼容)。

分期建议

P1(高价值低成本):改名 + 词汇修复(已上线)、概览条、佐证过滤 chips、删除确认。
P2(核心补齐):编辑抽屉 + 字段模板 + 佐证行管理(Read 后已有 PATCH /materials/{id} 契约,前端补 UI 即可)。
P3(增强):字段完整度统计、搜索字段值、历史标书复用入口。

测试影响

现有 LibraryView 断言(类型过滤 / 新建 / 空态)基于文本与角色,徽章与文案改动需同步更新;新增建议:佐证过滤切换、抽屉字段行增删、past_bid 新建成功(回归本次词汇 bug)。后端零改动,make test 契约测试不动。
