## 三、本轮新识别盲区(原 TODOS 未覆盖)

| # | 盲区 | 说明 | 级别 |
|---|------|------|------|
| B1 | **审阅角色授权** | 消解面板横幅自述「第一版仅超管可审, 正式审阅角色授权为后续批次」; 权限门仅 system:access 一刀切——审阅者/建模者/只读未分。多人使用前必须解决(否则任何有权限者可驳回/合并/停用规则) | 中(多人化前置) |
| B2 | **操作审计日志** | 审核确认/驳回/合并/规则启停/快照恢复/装载——均无 who 记录(history jsonl 只有"发生了什么"无操作者)。单人工具低危, B1 落地时必须配套 | 中(随 B1) |
| B3 | **通知/告警** | 任务失败、违规突增、装载失败——无任何主动通知(内部单人工具可接受; 半无人值守时需要) | 低 |
| B4 | **registry 变更回滚 UI** | 建模器误保存后无界面回滚(yaml 在 git 有历史但需手工操作; 快照是数据非定义) | 低 |
| B5 | **CQ 库扩充机制** | CQ 仅 4 条种子(1 条已停用)——本体工程实践要求 CQ 随域演进持续扩充, 无维护入口/规范 | 低 |
| B6 | **mention 治理常态化** | 零边 mention 清除是一次性动作; 增量装载会再积累(与实体孤儿同)——建议随版本定期跑治理面板或挂调度 | 低(与 G1 同基建) |

## 四、明确不做(边界记录)

- 本体版本发布流/审批流(单人知识工程组, git 历史+快照已覆盖)
- 增量推理(千级规模全量重算秒级, bug-2188 语境已消失)
- GB/T 48000.3 §6.2 标准实体目录(适用范围外, §4.4 重评触发条件已定义: 标准数字化平台对接或标准知识域立项时重评)
- 投标域数据接入本内核(走独立平台模块; qualified_bidder 规则已停用保留, 数据接入一键恢复)

## 五、优先级建议(按运营视角 A 排)

1. **近期(运营补齐)**: G6 抽取进度(S) + B6 治理常态化挂调度(随 G1)——日常体验小件
2. **中期(多人化前置)**: B1 审阅角色授权 + B2 操作审计(合并一项设计, 多人使用前必须)
3. **中期(第二域接入时)**: G4+G5 多域化两条(管线+消费端一起设计)
4. **远期**: G3 直连抽取、G1 快照调度、G2 跨域、B3/B4/B5 按需
