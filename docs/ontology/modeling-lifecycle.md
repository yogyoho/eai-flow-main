## 1. Phase A — 建模设计（页面 05 本体建模器）

**方法学依据**：Gruber 五原则（清晰/一致/可扩展/最小编码承诺）+ METHONTOLOGY 概念化阶段。
**前置**：明确本域要回答的能力问题（Competency Questions, 3-5 条）——这是后续 06 推理台的验收判据。

### 操作步骤
1. **设计类层次**：在"类层次"树中规划 etype → OWL 类映射（`etype_classes`），声明 `subClassOf`（父类必须在同域已声明）。
2. **填写类元数据**：每个类按国标附录 A 八项补齐——IRI（自动=ns+ClassName）、名称、标签（中文）、定义、属性集、父类、子类、等价类。
3. **声明谓词**：在关系对象 `predicate` 枚举中登记域内谓词（如 `treated_by / governed_by / monitored_by`）。
4. **编写公理（formal 段）**：
   - `property_chains`：≥3 段逻辑链自动生成 CONSTRUCT 规则；2 段由 owlrl prp-spo2 直接物化；
   - `transitive`：传递谓词（如 `part_of`）；
   - `inverse`：逆属性对；
   - `disjoint`：互斥类组；
   - `hasKey`：全局唯一标识属性。
5. **点击「校验建模面」** → lint fail-closed 检查（IRI 冲突/label-definition 必填/引用可解析）。
6. **点击「保存并热重载」** → registry SHA 变化 → schema 图自动重编 → 下次推理闭包使用新公理。

### 验收门
- 建模面校验 0 错误；
- 每类 label/definition 非空（C4 附录 A 检查项）。

> ⚙ 当前形态：建模面 = 编辑 registry yaml（`app/ontology/registry/<域>.yaml`）+ 热重载；建模器页为可视化预览，表单化编辑待接。

## 2. Phase B — 知识获取（页面 08 抽取导入）

**方法学依据**：NeOn 情景 2（本体与数据协同演化）——本体不是一次建成，与数据迭代共生。

### 操作步骤
1. **投放文档**：上传样例报告（.txt/.docx；.doc 先走 doc_convert）。
2. **触发抽取**：管线执行四类目标抽取——
   - ① 章节结构（Report/Chapter/Section + `has_chapter/has_subsection/part_of`）；
   - ② 逻辑链条（治理合规链 `treated_by→governed_by→monitored_by`；影响链 `emitted_as→threatens`）；
   - ③ 标准阈值/法规条款（GB/HJ 标准号、限值 pollutant/op/value/unit、《法》第X条）；
   - ④ 佐证需求（表/图/公式/附件/流程图引用）。
3. **装载断言图**：抽取结果经 `/formal/load-ontology` 写入 kernel（实体 uuid5 确定性、重复装载幂等）。
4. **核对装载统计**：entities/relations/skipped 清单——跳过项即"谓词越域/端点缺失"待人工研判。

### 验收门
- 装载统计 0 悬空引用；
- 低置信度（<0.70）实体标记为仅存证（不入推理空间）。

> ⚙ 当前形态：抽取 = 确定性正则/启发式（`extract_ontology.py`）；LLM 辅助精标为后续增强。页面骨架已就位，数据面走 `/formal/load-ontology` 接口。

## 3. Phase C — 质量校验（页面 07 校验中心）

**方法学依据**：SHACL 闭世界约束管写路径 + 国标 GB/T 48000.3 §5.3 符合性。

### 操作步骤
1. **查看 SHACL 违规**：每条违规含 focusNode/path/message/severity/source 五字段。
2. **逐条修复**：按 source 定位 shape → 修正数据或抽取规则 → 重跑校验直至 0 violation。
3. **核对国标五项**：IRI 命名（§5.4）/ 序列化往返（§5.3）/ SHACL 报告（§5.3）/ 附录 A 元数据 / §9 扩展原则。

### 验收门
- `conforms = true` 且 0 violation；
- 国标五项 5/5 通过。

---

## 4. Phase D — 消解审核（页面 04 消解审核）

**方法学依据**：实体消解的 sameAs 纪律——推理层只产候选，**合并永远人工确认**。

### 操作步骤
1. **处理候选等价对**：每对显示相似度（0.92 审核带自动入围）+ 证据重合依据。
2. **三选一裁决**：确认合并 / 判定不同实体 / 稍后。
3. **确认合并** → `mergedInto` 指针 + `MergeAudit` 审计节点（actor/时间/依据 mention 全留痕）。
4. **误合并撤销**：操作历史中"撤销合并"——指针回翻 + `auditReversed` 留痕，可重复审计。
5. **置信度纪律**：≥0.92 进审核带可一键合并；0.70–0.92 进推理空间不自动建议；<0.70 仅存证。

### 验收门
- 待审队列清零（或遗留均有裁决记录）；
- 每次合并/撤销均有审计节点可回放。

---

## 5. Phase E — 推理验证（页面 06 推理工作台）

**方法学依据**：能力问题（CQ）验收——本体建得对不对，看它能否回答注册的问题。

### 操作步骤
1. **全量重算**：schema 重编 → owlrl OWL 2 RL 闭包（置信度 ≥0.7 门）→ CONSTRUCT 派生（每规则独立 named graph）。
2. **核对三张瓦片**：entailment 物化数 / CONSTRUCT 派生数 / 闭包耗时（5k 实体 ≤15s 校准门限）。
3. **逐条验收 CQ**：
   - "图谱可答" → 02 图谱浏览检索/遍历直接命中；
   - "推理可答" → 06 物化结果中可查（如 `covered_by_standard` 治理链、`qualified_bidder` 资格预审）。
4. **规则管理**：新增/调整 CONSTRUCT 规则（`rules.yaml`）→ dry 运行 → 全量重算。

### 验收门
- 注册的全部 CQ 均可答（图谱可答或推理可答）；
- 闭包 0 errors（失败自动降级保留旧物化）。

## 6. Phase F — 探索确认（页面 02 图谱浏览）

### 操作步骤
1. **检索定位**：顶栏搜索实体名 → 候选下拉 → focusNode 定位。
2. **双层切换**：「断言+物化」看全部（虚线=推理边）／「仅断言」看原始事实。
3. **节点详情**：点击节点 → 右栏属性/证据链 mentions/推理物化清单——**每条事实可溯源到原文引用**。
4. **社区着色**：按 Louvain 社区分色观察簇结构。

## 8. 监控与治理（页面 01 工作台总览）

- **建模管线状态流**：抽取→校验→消解→推理→导出 全链路健康度；
- **操作留痕**：合并审计/撤销/推理刷新时间线（永不删除）；
- **失败判据**（自 methodology §6.3 继承）：6 个月内无跨模块问答真正用到推理派生事实 → 暂停扩张回查需求；
- **快照调度**：每日 06:00 Turtle 快照（恢复手段 = 国标交付物，一鱼两吃）。

## 9. 迭代循环

新域接入 = 重走 A→G（如 eia 域实测：registry 增益 +2 行、域表新文件、抽取器新词表）。
