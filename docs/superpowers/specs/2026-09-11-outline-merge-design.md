# Design: 大纲自拟结构化（B1 v1→v2 outline_merge）

Generated by /superpowers:brainstorming on 2026-09-11
Branch: main-dev-fork
Status: APPROVED（用户逐项定案：只接管无锚点条款 / 对话协议确认门 / 方案 1 落地机制）
前置: Plan 3（bid-technical B1 v1 对话协议大纲 + tech_outline_packs 16 类已填充）、structure.json `origin: mirror|self_created` 既有机制

## 1. 问题与目标

v1 大纲自拟只产出人读候选文档（candidates/tech_outline.candidates.md），确认后**不落 structure.json**——技术卷渲染的章组织仍来自招标格式章镜像，无锚点条款全部落"其他技术要求响应"兜底节。v2 目标：**确认后的大纲章落成 structure.json 的结构化章树**（`origin=self_created`），使 build --docs technical 按 B 自拟大纲组织章节、progress 章门按大纲章推进。

**语义边界（用户定案）**：大纲**只接管无锚点条款**——招标已规定格式锚点的技术条款仍走镜像挂接，镜像纪律不破。

## 2. 数据形态：大纲候选双文件（candidates/，Agent 可写区，不受铁律 9 管辖）

```jsonc
// candidates/tech_outline.candidates.json —— outline_merge 的唯一机器输入
{
  "source_pack": "it-full",            // 装载的骨架 slug；自由拟时 null
  "confirmed": false,                   // 展示态留痕(对话确认后由 Agent 置 true); 硬闸是 merge 的 --confirm-outline flag(§3), 本字段不参与校验
  "chapters": [
    { "no": 1, "title": "项目总体理解", "clause_ids": ["ZB-T-001"], "notes": null }
  ],
  "managed_node_ids": []                // merge 回写：本轮大纲创建的 S-NNN 列表（重跑精准替换的依据）
}
```

- `candidates/tech_outline.candidates.md`：人读呈现（v1 延续，对话确认的载体）。
- 候选由 Agent 落盘与更新（与既有候选 checkpoint 同权限）；`outline_merge.py` 只读它 + 回写 `managed_node_ids`。

## 3. `outline_merge.py`（A 的 scripts/，canonical；B 经绝对路径调用）

**确认闸**：不带 `--confirm-outline` 拒绝执行（exit 1，同 `state_guard sign --confirm-gate1-edit` 纪律）——对话口头确认后 Agent 才带 flag 跑；脚本 stderr 呈现章组×条款计数摘要。

**挂接校验（fail-closed，绝不半落地）**：每个 `clause_ids` 必须：① 存在于 clauses.json；② 活条款（未 superseded/voided）；③ `category ∈ {technical, service}`；④ 未被任何 `origin=mirror` 节点的 `linked_clause_ids` 挂接。违者逐条列出拒绝（kind: `not_found` / `not_live` / `wrong_category` / `mirror_anchored`）。

**节点生成规则**：
- 只新增/替换 `volume=technical` + `origin=self_created` 的章节点；mirror 节点一个不碰。
- 章节点 `slot_type=group`；`path` 与镜像 path 空间隔离（自拟前缀命名空间，复用 build_output 既有 self_created 不占镜像号的编号规则——计划期实读 `render_doc_booklets` 编号段定稿字面格式）。
- `required_format.desc` 写入大纲来源标记（pack slug 或 "自由拟"）；免格式校验由 origin 既有语义天然获得。
- **精准替换**：先删 `managed_node_ids` 中的旧节点（及其挂接）再落新树 → 回写新 `managed_node_ids` 进候选文件。responses.py 兜底创建的自创节点**永不在 managed 集合内**（不受影响）。
- **覆盖检查**：merge 后统计仍无任何锚点的活技术条款数进 summary（`remaining_unanchored`）；≠0 仅提示（仍走 responses 兜底），不阻断。
- **重签**：落盘后经 state_guard 签名通道重签 structure.json（与 extract.py merge 同机制）。
- **幂等**：同一候选重跑字节一致。

## 4. B1 工作流 v2 与门协议（对话协议，用户定案）

1. 装载 pack（tech_outline_packs 16 类）或自由拟 → 生成候选 json+md。
2. 对话呈现章组×条款映射+骨架偏差 → 用户口头确认。
3. `outline_merge.py --state-dir … --candidates … --confirm-outline` → 落章树+重签 → stdout 单行 JSON 摘要（新增/替换/remaining_unanchored）。
4. B2 响应生成的锚点因此有了家；**大纲 merge 前不跑 responses merge**（响应候选可先行生成，落账在大纲落地后）；无大纲场景（用户拒绝自拟）responses 零散兜底路径不变。
5. SKILL.md（bid-technical）B1 节的"不直写 structure.json"边界改写为此机制；铁律附加条注明：门1 后修 structure 经 outline_merge 重签通道，授权级别等同确认门1 class 修订。

## 5. 渲染与既有机制交互

- 镜像章渲染不变；self_created 章树按既有渲染通道（免格式校验、确认门排除指纹核对均为 origin 既有语义）。
- progress.py init 从 structure 枚举章集合时自然纳入大纲章（章门按大纲章推进）。
- score_simulate 重灌锚点=path 基（既有），大纲章 path 稳定即可，无额外适配。

## 6. 错误处理汇总

| 失败 | 处置 |
|---|---|
| 缺 `--confirm-outline` | exit 1，提示确认纪律 |
| 候选 JSON 损坏/字段缺失 | exit 1 指明字段 |
| clause_ids 校验失败 | exit 1 逐条列出 kind（四种） |
| mirror 节点被候选波及 | 不可能（只新增 self_created；校验 ④ 拒绝抢挂） |
| state_guard 重签失败 | exit 1，structure.json 不落盘（先写临时+校验+原子替换+签名的既有管线顺序） |
| 全部章 clause_ids 为空 | exit 1（空大纲无意义，拒绝） |

## 7. 测试矩阵

- outline_merge 单测：候选校验四类 fail-closed / 空大纲拒绝 / 幂等重跑 / 重跑精准替换（managed_node_ids 对齐，兜底自创节点不受影响）/ mirror 节点零触碰 / 重签生效（篡改检测）/ `remaining_unanchored` 计数。
- 消费测试：build --docs technical 渲染大纲章树（章标题/条款条目落位）；progress init 纳入大纲章。
- 契约测试：bid-technical SKILL.md B1 v2 文案（引用 outline_merge 命令）；A SKILL.md 速查表不动（B 专属命令进 B 速查表，A 的防幻觉契约枚举追加 outline_merge 子命令说明）。

- 大纲对镜像章的重排/归并（用户定案排除）。
- 多候选大纲版本管理（单候选文件，重跑即替换）。
