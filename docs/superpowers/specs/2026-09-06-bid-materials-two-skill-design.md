## 1. 总览：三个交付单元

```
┌─ 投标资料管理 app（新独立 extension: bid_materials, app_center 注册）
│    ├─ 投标资质管理: BidQualification + BidQualificationVersion(MinIO 版本库)
│    └─ 投标方案-技术资料库: BidSample(样例台账, KFSample 形态沿用)
├─ Skill A: bid-proposal-overall（整体投标方案编制）
│    招标文件→义务清单→门1→补遗→build 整体方案册集(商务全量+技术占位页)+资质册装配+报价 SLOT
└─ Skill B: bid-technical（投标技术卷）
     技术条款(来自 A 的 extract)→技术卷大纲自拟→逐条款响应(样例检索仿写/编造+深度目标)→章门→build 技术卷册集
```

共享: workspace/state（clauses/structure/responses/slots 同一项目权威态）、`scripts/` 全套（canonical 在 Skill A 目录）、outputs/投标文件/（两 skill 的册集同目录，manifest 合并语义见 §5）。

## 2. 投标资料管理 app（bid_materials extension）

### 2.1 数据模型

```python
class BidQualification(Base):            # 资质元数据行
    __tablename__ = "bid_qualifications"
    id: UUID pk
    qual_type: str(50)                   # 营业执照/CMMI/ISO9001/业绩证明/软件著作权…(字典表可扩)
    cert_no: str(200)                    # 证号(白名单导出字段)
    issuer: str | None                   # 发证机构
    valid_until: Date | None             # 有效期至(到期预警源)
    scope: str | None                    # 适用范围
    current_version: int                 # 当前版指针(回滚=改指针)
    org_scope: str | None                # 部门/组织可见范围(对齐 knowledge 部门可见模式)
    notes: Text | None
    created_by/created_at/updated_at

class BidQualificationVersion(Base):     # 版本行(不可变, 只追加)
    __tablename__ = "bid_qualification_versions"
    id: UUID pk
    qualification_id: UUID FK
    version: int                         # 递增
    minio_key: str(500)                  # {qual_id}/v{n}.{ext}
    sha256: str(64)                      # 内容去重(同证同哈希不重复建版)
    file_ext: str(10)                    # png|jpg(魔数校验后落)
    file_size: int
    note: str | None                     # 换证/年审/初次登记
    uploaded_by/uploaded_at

class BidSample(Base):                   # 样例台账(沿用 KFSample 形态)
    __tablename__ = "bid_samples"
    id: UUID pk
    title: str(500)                      # 项目名(如"江西师范大学课堂观测系统")
    source_path: str(1000)               # 脱敏册相对路径(skills/.../references/samples_bank/…)
    file_hash: str(64) unique index      # 脱敏册 sha256(幂等入库键)
    industry: str(50) index              # 行业(招投标分类体系, 见调研文档 16 类)
    project_category: str(50) index      # 项目类别(IT软件平台/工程/货物/服务…)
    scenario: str(50) default "bid_sample"
    status: str(30) default "indexed"    # indexed|ragflow_pushed|disabled
    notes/created_by/created_at/updated_at
    # 深度地板不走册级字段——统一由 depth_targets.json 的 absolute_floor(全库 P25)承担,
    # build 无状态读取; 册级差异体现在命中组的 runtime median, 不预存。
```

### 2.2 MinIO 布局与访问（资质文件 png/jpg）

- 独立桶 `bid-qualifications`（与 ocr 桶隔离）；对象键 `{qual_id}/v{n}.{ext}`——**版本不可变只追加**，"当前版"=元数据行指针
- **写入**：后端代理上传（权限校验 → png/jpg 魔数校验 → sha256 与既有版本比对去重 → MinIO put → 建版本行 → 更新 current_version）
- **读取**：后端代理流式下发（权限校验后返回文件流；presigned URL 留作后续优化，一期不暴露桶地址）
- **删除**：软删（元数据标记 disabled；MinIO 对象保留——资质文件误删=灾难）
- **回滚**：改 current_version 指针（不删任何版本行）

### 2.3 API（router 前缀 /api/extensions/bid-materials）

| 端点 | 方法 | 说明 |
|---|---|---|
| `/qualifications` | GET/POST | 列表(过滤: 类型/到期窗口/关键词)/新建元数据 |
| `/qualifications/{id}` | GET/PATCH/DELETE(软删) | 详情(含版本列表)/更新元数据/软删 |
| `/qualifications/{id}/versions` | POST(multipart 上传)/GET | 新版本(png·jpg 魔数校验+sha256 去重)/版本历史 |
| `/qualifications/{id}/rollback` | POST {version} | 回滚当前版指针 |
| `/qualifications/{id}/file?version=n` | GET | 代理流式下发(默认当前版) |
| `/qualifications/expiring?days=90` | GET | 到期预警清单(30/90 天窗) |
| `/qualifications/export-whitelist` | GET | entities_whitelist 增量 JSON(实体名+证号——WP-2.4 组织级权威源) |
| `/samples` `/samples/{id}` `/samples/bulk` | GET/POST/POST | 样例台账 CRUD/bulk(registration.json) |

## 3. Skill 拆分：bid-proposal-overall / bid-technical

### 3.1 目录形态与安装约束

```
skills/public/bid-proposal-overall/     # Skill A（原 bid-proposal-writing 重组）
├── SKILL.md                            # 阶段0-3 + build --docs overall + 资质册装配 + 速查表(全量脚本, 含 --docs 旗标)
├── scripts/                            # ★ 全部管线脚本 canonical 位置(10+bank_compile 无, bank_compile 在 B)
└── references/                         # stage0-2 / stage3 / build-overall(新) / extraction_prompt / classification / schemas×4
skills/public/bid-technical/           # Skill B（纯编排技能：SKILL.md+references，无自有 scripts）
├── SKILL.md                            # 大纲自拟→供源级联(样例检索/编造+深度目标)→progress 章门→build --docs technical
└── references/                         # tech_response_prompt / tech_outline_packs/(16类骨架, 后续填充) / build-technical / 命令速查表(指向 A 的脚本绝对路径)
安装约束: B 依赖 A（pair-install——B 消费 A 的 scripts 与 state，不可独立分发）。拆分收益（商务节奏与技术创作节奏分离、教材各自聚焦）大于分发耦合代价。
```

### 3.2 build_output.py 多文档旗标与 manifest 合并语义（两 skill 共享输出的核心契约）

- 新增 `--docs overall|technical|all`（默认 all，兼容现有调用）
- **manifest 合并语义**：build 读既有 manifest → 更新本次 `--docs` 范围内的册条目 → **保留范围外条目**（A build 不清 B 的技术卷册，反之亦然）→ deliverables = 合并集
- **清场收窄**：只删本次 `--docs` 范围前缀的 stale 项（overall=整体方案-*；technical=技术卷-*；all=两者）
- **索引卷分区重写**：索引卷含两组清单——`--docs overall` 只重写整体方案组、保留技术卷组原样，反之亦然；`all` 重写两组
- 副表归属：偏离表/覆盖率/人核清单/实体lint 报告**跨两卷聚合 → 归 `all` 范围专责重建**；`--docs overall|technical` 单独 build 时保留既有副表不触碰
- `.delivery-contract` 标记与凭据：任一 skill build 成功即激活/更新（契约线程级，不受 --docs 影响）

### 3.3 A→B 接缝契约

- Skill A 技术占位页引用 Skill B 索引卷（指针可解析校验已有：占位完整性断言）——B 未跑时占位页显示"技术卷编制中"
- Skill B 大纲自拟输入 = A 的 extract 产物（technical/service 活条款）+ 评分办法 + tech_outline_packs 骨架（16 类分类体系，调研文档 bid-tech-outline-packs-research.md）
- 评分办法聚类：按评分项关键词把条款聚到骨架类别（确定性关键词匹配起步，聚类质量进人核）

## 4. 样例库与深度门

### 4.1 bank_compile.py（Skill B scripts/，离线一键，stdlib 自包含）

```
输入: 原始标书(md 或 docx 内置极简文本抽取≈30行, 不 import ingest——D7 自包含) + --map 脱敏对照表(维护者提供)
 stages:
  1 脱敏: 确定性规则——公司后缀扫描→某公司【N】/ 金额模式(¥?[\d,.]+万?元)→**** /
    统一社会信用代码(18位)→**** / 证号模式(--map 显式) / 人名(--map 显式, 人名无确定性识别)
    + 残留扫描报警: 金额/信用代码正则复扫, 命中即 rc=1 不出库(不静默)
  2 切片: H1/H2 章边界 → samples_bank/chN__{源}.md(保留"(格式)"标题逐字——1:1 纪律)
  3 指纹池: ≥100 数值抽取入库(供未来 SL3 防抄错库变体, 本期只采集不消费)
  4 bank_index.json: 切片清单+sha256+段长分布(重跑字节一致)
  5 depth_targets.json: absolute_floor=P25(全库段长) + 全库 median(参考值)
  6 registration.json: BidSample/切片登记行(供 bid_seed_samples.py 入库)
  7 RAGFlow 推送: 脱敏全册 → bid_samples 域(env BID_RAGFLOW_DATASET_ID; 失败=warnings 不阻塞, 本地衍生物已可用)
输出: references/samples_bank/ + bank_index.json + depth_targets.json + registration.json
```

### 4.2 bid_seed_samples.py（backend/scripts/，backend uv 环境）

读 registration.json → BidSample 入库(file_hash 幂等) → 触发 RAGFlow 域绑定校验。precedent: eia 会话 kf_seed_samples.py。

### 4.3 检索接线（stage4a 第一层落地形态）

- 按章组批量（6A）：每章组一次 RAGFlow filters 查询（`doc_type=bid_sample` + 行业/类别）召回 top-K 段落 → 本地条款关键词二次匹配到 clause_id 组
- **命中组深度目标（响应级，Q2 定案）**：`target = median(命中样例段长) × 0.6 × 覆盖缩放`；无命中组 → 无目标（只受 floor）
- stage4a 将 `depth_target`（数值+命中组签名）写入 responses.json 候选可选字段——validate 校验形态；**build 无需检索**（读字段比对），保持无状态

### 4.4 深度门（build_output 集成）

- 逐条 `response_text` 实质长度（剥空白/标点，复用 WP-C 口径）比对 `depth_target`：
  - 有 target：`实质长 ≥ target×0.6×覆盖缩放` → PASS；不足 → anomaly `depth_below_target`
  - 无 target（编造/无命中）：`实质长 ≥ absolute_floor` → PASS；不足 → anomaly `depth_below_floor`
- anomaly 落 lint 报告"深度"节 + progress 章门 FAIL detail（与实体门同通道，回 stage4a 补写；**非凭据阻断门**——深度是质量牵引非废标风险）
- 三份真实标书跑 bank_compile 作为验收样例（脱敏正确性人工走查 + 基线合理性）

## 5. 错误处理汇总

| 失败 | 处置 |
|---|---|
| bank_compile 脱敏残留扫描命中 | rc=1 不出库（不静默） |
| RAGFlow 推送失败 | warnings+本地衍生物可用；重试手动 |
| 检索超时/空 | P1 政策自然降级编造+floor |
| MinIO 上传非图片/超限 | 400 魔数/大小拒绝 |
| 合并导出任一册失败 | 400 指认册名整单中止（已实现） |
| 深度不足 | anomaly+章门 FAIL（质量牵引，非凭据阻断） |
