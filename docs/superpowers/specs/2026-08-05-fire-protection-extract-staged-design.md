# fire-protection-extract 技能分阶段重构设计

- 日期：2026-08-05
- 状态：已评审待实施
- 涉及技能：`skills/public/fire-protection-extract/`（运行时 `backend/.deer-flow/skills_view/public/fire-protection-extract/`）
- 关联：上一轮空章节根因（bug-1044）在本文档一并根治

## 1. 背景与问题

### 1.1 现状缺陷

对 `fire-protection-extract` 技能逐文件核查 + 真实线程（68c225b9）执行回放，确认四个结构性缺陷：

1. **无"阶段"维度（核心缺陷）**。契约库 3 份契约（`仓库项目.json` / `基地项目.json` / `基地综合大队消防站.json`）+ 默认模板 `fire_spec_mapping.json` 全部是**同一套 28 节"基础设计"大纲**。连 `仓库项目.json` 也错误地用了基础设计大纲，而初步设计阶段报告真实大纲是 7 章，二者章节结构明显不同。
2. **契约格式漂移（bug-1044）**。`extract.py` 已迁移为段落索引格式（`paras:[i]`），但 `contracts/基地项目.json`（2026-07-05 保存）仍是旧字符串锚格式（`anchor`/`para_run from-to`），且 `extractor_rules.md` 仍记录旧 schema。旧契约被新引擎加载 → 25 个段落来源全部输出 `[⚠未找到段落: None]` → 报告大部分章节为空。
3. **报告标题硬编码 `XX`**。`run.sh` 调 `extract.py <struct> <mapping> <report>` 不传项目名，`extract.py::build_report` 默认 `project_name="XX"`，标题永远是 `# XX 消防设计专篇`。
4. **阶段模板文本不同**。两个阶段的第 1 章模板内容完全不同（初步设计=旧版标准 GB50016-2006/GB50058-92…；基础设计=新版标准 GB50016-2014…），当前统一填基础设计清单 → 初步设计报告"抄错"。

### 1.2 分阶段事实（来自样例）

| | 初步设计（仓库项目样例） | 基础设计（基地项目样例） |
|---|---|---|
| 源文档 | 仓库项目-总说明书.docx | 基地项目-设计说明书.docx |
| 专篇结构 | **7 章**（设计依据/项目概述/火灾危险性分析/防火安全措施/消防系统设计/投资概算/图纸表格） | **8 章**（设计依据及采用的标准/概述/火灾危险性分析/防火安全措施/消防设施/灭火救援设施/投资概算/图纸表格） |
| 独有章节 | 设计范围(2.2)、工程的消防环境状况(2.4)、区域位置(2.5)、安防监控系统(4.2)、防雷接地及照明(4.4)、第5章"消防系统设计" | 地方法规(1.3)、项目位置/功能定位/气象/周围消防站(2.1-2.7)、建筑物通风措施(4.5)、视频监控系统(5.5)、第6章"灭火救援设施" |

| 源文档自带阶段标记 | 首段"初步设计" | 首段"基础设计" |

样例专篇与源文档逐段重叠率约 47%（正文逐字摘抄为主，其余为标题/表格/模板/需计算标注）。

## 2. 需求与已确认决策

**核心原则：能抄尽可能抄，且不能抄错。**
- 能抄 → 阶段大纲选对、源文档有的内容尽量摘全（摘抄完整性）。
- 不能抄错 → 阶段模板不串、项目锚点不跨项目复用、源文档没有的数据显式 `[需计算]`/`[⚠未找到]` 而非编造。

已确认决策（用户拍板）：

1. **阶段判定**：自动识别 + 用户可覆盖（用户请求显式说"初步设计/基础设计"优先 > 源文档首段扫描 > 文件名 > 默认基础设计）。
2. **结构保真**：章节标题/顺序/层级**严格照搬样例大纲**，AI 不得自创章节或改动标题。
3. **契约架构**：**阶段大纲 + 项目锚点两层分离**。
4. **交付格式**：保持 `.md` 输出；docx 导出作为独立后续步骤（现有"导出 docx"）。

## 3. 设计

### 3.1 阶段层（Stage Layer）

**阶段识别**（`run.sh` 第 0 步新增 `detect_stage()`）：
```
优先级 = 显式参数(--stage/第3参) > 源文档首50段扫描("初步设计|基础设计") > 文件名(总说明书→初步设计, 设计说明书→基础设计) > 默认基础设计
```

**阶段大纲文件**（新建，标题从样例正文逐字提取）：
```
references/stage-outlines/初步设计.json
references/stage-outlines/基础设计.json
```
每个大纲含：
- `report_title` 模板（含阶段：`{项目名} 初步设计 消防设计专篇`）
- `sections[]` 骨架：`fire`(逐字标题)、`class`(heading/verbatim/template/compute)、`heading_level`、`template` 引用
- `templates{}`：按阶段的标准清单 + 法规（见附录 A 的逐字文本）
- verbatim 节附 `guide[]`：E3 批量搜索关键词（每个 verbatim 节 3-5 组）

### 3.2 契约层（Contract Layer）

```
contracts/初步设计/{项目类型}.json    ← 只存各节 sources(段落索引) + _stage + _outline_version + _fingerprint
contracts/基础设计/{项目类型}.json
contracts/_index.json                 ← {stage: {项目名: 指纹}}
```

`contract_store.py` 改造：
- `save(name, stage, mapping, struct)` → 按阶段子目录落盘。
- `find(struct, stage)` → 阶段内指纹匹配；同分时按 `_saved_at` 新者优先（修复同指纹命中旧契约）。
- **格式校验内置**：加载的映射若含旧字符串锚（`anchor`/`from`）→ 报 `CONTRACT_FORMAT_MISMATCH` 硬失败，绝不静默产出空报告。

**现有契约迁移**（一次性）：
- `仓库项目.json` → `contracts/初步设计/仓库项目.json`（按新格式重建，大纲用初步设计 7 章）
- `基地项目.json` → `contracts/基础设计/基地项目.json`（旧字符串锚转段落索引）
- `基地综合大队消防站.json` → `contracts/基础设计/基地综合大队消防站.json`

**E3 流程更新**：基于所选阶段大纲的 `guide[]` 关键词，一次批量脚本搜全部小节 → 生成各节 sources（每节 3-8 段）→ `save(name, stage, …)` → 重跑。E3 产物只含锚点，不含大纲。

### 3.3 引擎改造 + Bug 修复

- `extract.py`：签名改为 `extract(struct, outline, mapping)`（大纲供骨架+模板，映射供 sources）；新增 `project_name` 参数 → 修复 `XX` 标题。
- `run.sh`：第 0 步 `detect_stage()`；第 2 步加载阶段大纲 + `find(struct, stage)` + 格式校验硬失败；传 `project_name`+`stage` 给 extract.py。
- `grounding_check.py`：适配两层；新增**阶段大纲完整性检查**（大纲每个 verbatim 节必须有映射来源，否则判失败）。
- `SKILL.md`：更新流程（阶段说明 → 按阶段选大纲 → E3 用 guide 批量生成 → 展示）；保留"相关性扫描 C 方案"与"禁止自行改写正文"铁律。
- `extractor_rules.md`：更新 schema 到新格式（当前与引擎矛盾的旧文档同步）。

### 3.4 "能抄尽可能抄，且不能抄错"落地

**摘抄完整性**：
- E3 引导词 `guide[]` 从样例推导；每节锚定 3-8 段（当前契约仅 1-3 段）。
- 表格按 `表号` 整表抄（样例大量用表：气象/建构筑物一览/用电负荷/通风特性…）。
- **覆盖率门槛**：`grounding ≥ 0.85` 且 0 个 `[⚠未找到]` 才 PASS；未达则提示"E5 校准或 E3 重跑"，不再静默出空报告。

**防错墙**：
- 阶段模板锁死：标准清单/法规按阶段大纲取，阶段间不串。
- 项目锚点每次 E3 按本项目文档重新生成，不跨项目复用。
- 源文档没有的数据 → 显式标记，绝不编造。

### 3.5 测试

**单元测试**（`backend/tests/test_fire_protection_extract_staged.py`）：
- 阶段识别优先级（参数 > 文档 > 文件名 > 默认）
- 两层 extract 合并（大纲+映射）
- contract_store 阶段内 find/save、`_index` 按 stage 分组
- 格式不匹配硬失败

**样例集成测试**（4 个 docx 作 fixture，位于 `skills/public/fire-protection-extract/tests/fixtures/` 或复制）：
- 仓库项目·初步设计：输出大纲逐节 == 样例 7 章、标题含"初步设计"、grounding ≥ 0.85、0 处 `[⚠未找到]`
- 基地项目·基础设计：输出大纲 == 样例 8 章、grounding ≥ 0.85
- **回归**：重放旧字符串锚契约场景 → 必须硬失败而非出空报告

## 4. 实施顺序

1. 建 `references/stage-outlines/{初步设计,基础设计}.json`（从样例正文提取，含附录 A 大纲与模板文本）
2. `contract_store.py` 增加 stage 维度 + 格式校验
3. `extract.py` 两层合并 + 项目名参数
4. `run.sh` 阶段检测 + 流程改造 + 硬失败
5. `grounding_check.py` 适配 + 完整性检查
6. 迁移/重建 3 份现有契约
7. `SKILL.md` / `extractor_rules.md` 文档同步
8. 单元 + 样例集成测试
