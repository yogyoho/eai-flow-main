## 1. 问题陈述

编写者实际工作是**从设计说明书摘抄段落/表格/数据**重组为消防专篇，而非创作。难点：消防专篇按**消防主题**分章（防火措施/消防设施/救援），说明书按**专业**分章（工艺/总图/电气/电信/建筑/暖通/给排水），大纲**多对多、对不上**。现靠经验+关键字比对，易抄错。

**原则：能抄尽抄，但不能抄错。**

## 2. 对比实证（来自样本逐段比对）

消防专篇 ≈ 设计说明书的「消防投影」，内容**基本逐字相同**，仅重组：

| 消防专篇 | ← 说明书源 | 重合 |
|---|---|---|
| §2.2 功能定位 / §2.3-2.5 规模·内容·性质 | §1 概况 同名小节 | 逐字 |
| §2.6 气象表 表2.6-1 | §3.1 表3.1-1 | 同表同数据 |
| §3 主项表 表3.0-1 | §2.3 表2.3-1 | 同表 |
| §4.1 总平面/防火间距 | §3.2 + §3.7 | 拼接 |
| §4.2 防雷接地 / §4.3 供电安全 | §5.1 电气 | 大段逐字 |
| §4.4 建构筑物防火 表4.4-1 | §7.1 建筑 + 表7.1-1 | 逐字+同表 |
| §4.5 通风 表4.5-1 | §8.2 暖通 + 表8.2-1 | 逐字+同表 |
| §5.1 室外消防水 / §5.4 火灾报警 / §5.5 视频监控 | §9.2 消防 / §6.1 电信 | 逐字 |
| §6 灭火救援设施 | §3.7 消防道路 | 逐字 |
| 表5.4-1 电信用户表 | 表6.5-1 | 同表 |

**样本中实测到的"抄错"风险**（必须防）：
- **数值冲突**：§9.1 给水（生活水 8L/s、DN150）vs §9.2 消防（10L/s、DN200）；专篇取 §9.2。匹配错段落即抄错数值。
- **表名相近**：生活水质表/消防水表/给排水水量表都含"水"，语义检索易抄错表。
- **空单元格**：建构筑物表"火灾危险性分类"执勤楼留空，两份都空——照抄对，生成式会"补全"反而错。
- **漏抄/抄串**：§9.1 水泵参数（Q/H/P）专篇略去，需规则决定抄/省。
- **伪抄录**：§7 投资概算（样本 77 万合计）说明书里**根本没有**，是另算的——绝不能伪装成抄的。

## 3. 核心范式转变

**v2 = 生成式**（模板+指南从零写）→ **新技能 = 抽取-映射-校验式**（从说明书精确摘抄重组）。

## 4. 内容三分类（落实"能抄尽抄但不抄错"）

每个消防小节在映射契约里标注 `content_class`，**绝不混用**——把"该抄的"与"该算的"显式分开，就不会把计算值伪装成抄录值。

| 类别 | 含义 | 例子 | 处理 |
|---|---|---|---|
| `verbatim` 抄 | 逐字摘自说明书 | §2.2、§5.1、§6、各表 | 按地址精确复制 + 溯源校验 |
| `template` 填 | 固定结构+项目变量 | 封面、§1 标准清单（GB50160 等固定） | 模板填充 |
| `compute` 算 | 说明书无，需另算/补 | §7 投资概算 | 明确标 `[需计算]`，不假装抄 |

## 5. 选定方案：C（契约为主 + 语义兜底 + 逐字溯源校验 + 契约自演进）

- **映射契约为主**：契约覆盖的消防小节 → 按地址精确摘抄（方案 B 路径）。
- **语义兜底**：契约未覆盖 / 说明书结构异常 → 语义召回候选 + LLM 选定，**仍强制走逐字溯源校验**（方案 A 路径，但加了安全网）。
- **契约自演进**：兜底成功定位到的源**自动回写进契约**，下次走精确路径——契约越用越全，首跑校准成本摊薄。

> 选 C 而非纯 B：跨设计院/项目类型难免结构差异，纯契约首跑脆弱。选 C 而非纯 A：纯 A 抄错风险最高，与核心诉求冲突。

## 6. 组件设计

### 6.1 说明书解析器（扩展现有 `docx_to_md.py`）
- 输出**带稳定 ID 的结构树**：章节路径 `§3.7 > ¶2`、表格按**表号**索引（`表3.1-1`）。
- 段落编号化，原文不改。
- 复用现有 python-docx 路径 + stdlib 兜底。

### 6.2 映射契约 `references/fire_spec_mapping.yaml`（核心资产）
一次性从样本对建好，反复用。每个消防小节一条：
```yaml
fire_section: "4.1 总平面布置、防火间距及消防通道"
content_class: verbatim
sources:
  - {loc: "§3.2 总平面布置", rule: verbatim, span: "总平面布置简述"}
  - {loc: "§3.7 消防 > 总平面布置", rule: verbatim}
  - {loc: "§3.7 消防 > 消防道路", rule: verbatim}
conflict_priority: []          # 本节无数值冲突
```
**冲突字段权威源**示例：
```yaml
fire_section: "5.1 室外消防水（水量/管径）"
content_class: verbatim
sources:
  - {loc: "§9.2 消防 > 室外消防水系统", rule: verbatim, authoritative: true}
conflict_priority:
  - field: "生活用水量/管径"
    prefer: "§9.2 消防"        # 不取 §9.1 给水的 8L/s/DN150
    reason: "消防专篇口径以消防章为准"
```

### 6.3 抽取器
- 按 manifest 逐小节精确抽取，逐字复制，**不改写**。
- 契约未命中 → 语义兜底召回候选 → LLM 选定 → 仍走溯源校验 → 成功则回写契约。

### 6.4 逐字溯源校验器（安全网）
- 每个输出块必须能追溯到源文件一段**精确子串**；否则标 `[⚠非原文/待核]`。
- **覆盖检查**：每个消防小节要么映射到源、要么标 `compute/template`，否则报警"漏抄"。
- 空单元格/留白照抄通过（不触发"补全"）。

### 6.5 复用 v2 既有件
`docx_to_md.py`（解析基底）、`fire-regulatory-compliance-check` 10 项合规脚本（校验）、`write_file`+`present_files`（输出+文档空间同步）、knowledge-factory `kf_resolve_template`（取 8 章骨架与 content_contract）。

## 7. 工作流（6 步）

```
① 解析说明书 → 带ID结构树 + 表号索引
② 加载映射契约 fire_spec_mapping.yaml
③ 逐小节按契约抽取（verbatim按地址 / template填充 / compute标注 / 未命中语义兜底）
④ 逐字溯源校验（非子串→标红；漏映射→报警；冲突字段取权威源）
⑤ 三分类组装成 8 章报告（抄/填/算分明，每块带 [源:§x.x¶n] 标注）
⑥ 复用 v2 合规检查脚本验证 → write_file outputs/ + present_files
```

## 8. 防"抄错"四层防御

1. **按地址抽取**（非相似度）→ 防抄错段/抄错表。
2. **冲突字段权威源**（manifest 指定）→ 防抄错数值（§9.1 vs §9.2）。
3. **逐字溯源校验**（精确子串匹配）→ 防幻觉/漂移/改写。
4. **三分类 + 覆盖检查**→ 防漏抄、防把计算值伪装成抄录。

## 9. 边界与已知限制

- 首跑依赖人工校准契约（样本对一次）；之后自演进。
- `compute` 类（§7 投资概算）不在本技能自动完成范围，标 `[需计算]` 由人工/概算技能补——**不编造**。
- 附图清单（§8）从说明书附图目录摘，但图本身不存在 md 里，仅列清单。
- 输出仍为结构化 Markdown → 文档空间（docmgr）排版导出 Word（沿用 v2 铁律：一次 write_file + present_files，不直接生成 docx）。

## 10. 不做（YAGNI）
- 不自建向量库/嵌入服务（语义兜底用最小可用方案：标题关键字+段落TF或现成 embedding，够用即止）。
- 不做全文翻译/改写（违背"能抄尽抄"）。
- 不重复合规检查逻辑（复用 v2 脚本）。
- 不做投资概算自动计算（标 `[需计算]`）。

## 10.5 泛化路径（同类专篇：给排水/抗震/节能…）

「专篇 = 设计说明书的主题投影、内容基本逐字」是一个**通用模式**，不是消防特有。消防只是本框架的**第一个实例**。同类适配清单：

| 报告 | 适配 | 主源章节 |
|---|---|---|
| 给排水专篇 | ✅ 高 | §9 给排水为主 + §8 室内给排水 + §7 管井/防水 |
| 抗震设计专篇 | ✅ | §7.2 结构 + §3 地震地质 + §5 电气抗震（消防专篇目录已列"第四册 抗震设计专篇"） |
| 节能/环保/劳动安全卫生专篇 | ✅（部分算） | 各专业章拼 |
| 暖通/电气/建筑结构专篇 | ✅ 最高 | 几乎是对应专业章的直接切片 |
| 可研报告 / EIA环评 / 概算 / 合同价格分析 | ❌ | 非投影型（上游源/建模计算/无源可抄），走各自现有技能 |

**引擎与契约的文件分离（D3 的落地）**：本技能目录结构刻意把 report-agnostic 的引擎和消防专属契约/标准分开放，将来抽公共框架时直接 lift：
```
skills/custom/fire-protection-extract/
  scripts/parse_spec.py          ← 引擎：docx→带ID结构树+表索引（report-agnostic）
  scripts/extract.py             ← 引擎：按契约抽取+语义兜底（report-agnostic）
  scripts/grounding_check.py     ← 引擎：逐字溯源校验+覆盖检查（report-agnostic）
  references/fire_spec_mapping.yaml   ← 消防专属：8章×子节 源映射
  references/fire_standards.yaml      ← 消防专属：GB50160/50016… 合规标准
  references/extractor_rules.md       ← 引擎使用说明（契约 schema 在此定义）
```
将来给排水 = 新建 `skills/custom/drainage-report-extract/`，复用上面三个引擎脚本（或抽成共享 lib），只写 `drainage_spec_mapping.yaml` + `drainage_standards.yaml`（GB50015 等）。**本设计不为这个未来做任何额外抽象**——只在文件边界上留好口子。

## 12. 验收标准
- 用样本对跑通：消防专篇生成内容 ≥85% 块通过逐字溯源校验（verbatim 类应 100%）。
- §9.1/§9.2 数值冲突场景：必须取 §9.2，不得取 §9.1。
- 建构筑物表空单元格：照抄留空，不补全。
- §7 投资概算：标 `[需计算]`，不伪造数值。
- 10 项合规检查全部 PASS（复用 v2 脚本）。
