# 编辑器 AI 快捷操作 Backlog 与右侧 AI 助手定位

**日期**: 2026-09-05
**状态**: 定位与分工口径已确认（2026-09-05 用户认可）；功能 Backlog 待排期
**范围**: docmgr 编辑器内 AI 菜单（PersonalBlockNoteEditor / collab BlockNoteEditor 共用交互模式）

## 1. 背景

编辑器内 AI 现有快捷操作（选中文字 → Edit with AI → 下拉菜单）：

- **有选中**：润色 / 扩写 / 精简 / 续写
- **无选中**（仅 PersonalBlockNoteEditor）：续写 / 头脑风暴 / 生成大纲

技术管线：`setPrompt` 填入提示词 → 用户回车 → `POST /api/collab/ai-chat`（gateway 代理，读系统设置 default_model）→ LLM 输出 `applyDocumentOperations` 工具调用 → 客户端校验（**idsSuffixed 模式，operation id 必须带尾部 `$`**）→ diff 审阅（替换/撤销）。

BlockNote xl-ai 支持的操作类型：**update**（改写选中块）/ **add**（插入新块）/ **delete**（删除块）。

已知约束（历史 bug 沉淀，新增操作时同样适用）：

- 系统 prompt 必须显式教 LLM「operation id = 块 id + `$` 后缀」（bug-3100）
- 提示词菜单项经 `setPrompt` 填充；`AIMenu` 组件身份必须 `useCallback` 稳定，否则父组件重渲染会 remount 清空提示词（bug-3101）
- 「自定义指令」已天然存在：选中文字后直接在输入框输入任意指令回车即可——快捷菜单只是高频操作的捷径

## 2. 功能 Backlog（三档）

### 第一档：纯提示词即可支持（每项 ≈5 行菜单项代码）

| 操作 | 提示词要点 | 价值 | 操作类型 |
|---|---|---|---|
| 翻译（中→英 / 英→中） | 只输出译文，保持格式 | 对外合同、引进设备资料高频 | update |
| 校对纠错 | 只修标点/语病/错别字，不改风格，改动最小化 | 报告刚需；与润色的差异点 | update |
| 转为表格 | 将段落转为 `<table>` HTML（参数表/清单） | 工程文档结构化表达 | update（或 delete+add） |
| 转为列表 | 段落要点转无序/有序列表 | 同上 | update |
| 语气转换（书面化 ↔ 简洁化） | 保持信息量，只调语体 | 报告 vs 汇报讲稿 | update |
| 总结本段 | 提取要点 | 长段落精读 | update |
| 改写（换一种说法） | 保持原意，避免章节间重复 | 多章节文档 | update |

**领域特化（建议合入润色提示词）**：GB/HJ 标准的「应/宜/可/严禁」措辞分级约束、数字与 SI 单位格式规范——对设计报告价值高于通用润色。

### 第二档：需少量工程

| 操作 | 所需工程 | 说明 |
|---|---|---|
| 生成全文摘要（插入光标处） | 管线增加 `documentState.fullDocument` 注入 | 目前只注入选中块 |
| 按大纲续写下一节 | 复用编辑器已有 heading 提取逻辑，注入标题树 | 光标后起草整节 |
| 术语一致性检查 | 全文上下文注入 + 输出逐条建议 | 「给排水/消防」类术语统一 |

### 第三档：平台级（需立项）

- **知识库联动改写**：接 knowledge-factory RAG，按引用规范条文改写（需把 MCP 检索结果注入 ai-chat 管线）
- **全文审阅模式**：AI 以批注形式给全文建议（类 Word 审阅）
- **整篇翻译**：保持格式与术语表的整篇转换

## 3. 实施注意

1. **菜单项代码去重**：润色等操作目前在 PersonalBlockNoteEditor 内联 + collab 的 `aiMenuItems.ts` 各一份；新增前先抽成共享模块（如 `frontend/src/extensions/shared/editorAIMenuItems.ts`），两编辑器引用。
2. **菜单变长的可用性**：AIMenu 是带输入过滤的建议列表（支持 `aliases` 别名搜索），8+ 项后靠打字过滤定位；如超过 ~10 项考虑分组标题。
3. **新操作逐个过一遍已知坑**：`$` 后缀约定（后端系统 prompt 是否需要针对新操作调整）、中文 UTF-8（Windows shell 测试用 UTF-8 body 文件，勿内联中文 curl）。
4. **空 diff 体验**（enhancement 候选）：LLM 返回与原文几乎相同时审阅态无提示，易误判「功能坏了」。可在 gateway 检测 operation 内容 ≈ 原文时返回「该段已足够通顺，无需修改」类提示文本。

## 4. 右侧 AI 助手（DocAIAgentPanel）定位分析

### 4.1 两者架构本质不同

| | 编辑器内 AI（快捷菜单） | 右侧 AI 助手（DocAIAgentPanel） |
|---|---|---|
| 后端 | gateway `/api/collab/ai-chat` 直连 LLM（单轮、无状态） | **完整 LangGraph agent 子线程**（`type: docmgr-agent`，挂 `parent_thread_id`，可带 MCP 工具/知识库/skills） |
| 交互 | 选中即操作，diff 审阅，就地生效 | 多轮对话，操作以确认卡（OperationCards）呈现 |
| 上下文 | 选中的块（+少量文档元数据） | 跨消息积累的线程记忆 + agent 全部工具 |
| 适合 | 明确、原子、高频的局部修改 | 探索式、多轮澄清、跨文档、需要工具/知识的任务 |

### 4.2 结论：不替代，分层协作

即使第一、二档全部实现，**右侧 AI 助手仍应保留**，理由：

1. **需要 agent 能力的任务进不来行内管线**：「结合知识库里的规范检查这段是否合规」「参考上个项目的报告改写」——这些要 MCP 工具/RAG/多轮工具调用，只有 agent 面板做得到。
2. **意图不明确时需要对话**：用户说不清要怎么改时，行内快捷菜单无从下手；面板可先讨论再动手。
3. **跨文档/全文级任务**：整篇翻译、全文审阅（第三档）天然是对话式长任务。
4. **操作置信度分层**：行内 AI = 高频低风险（有 diff 审阅兜底）；面板 = 复杂操作 + 明确确认卡。

### 4.3 分工边界（产品口径，2026-09-05 用户已确认采纳）

- **选中文字的局部修改** → 编辑器内 AI（快捷菜单 + 自定义指令）
- **带工具/知识/多轮的任务、跨文档任务、全文级任务** → 右侧 AI 助手
- 联动点（未来可选）：面板对话中产生的修改建议，可一键「转到编辑器内应用」（复用 applyDocumentOperations 管线）

## 5. 排期建议

1. **第一批**（第一档中挑 3 个）：翻译、校对纠错、转为表格 + 共享菜单模块抽取
2. **第二批**：其余第一档项 + 领域特化润色提示词
3. **第三批**：全文摘要（第二档）
4. 第三档单独立项评估
