## Key Learnings

- **对话→文档空间同步的真正路径是 sync_thread_files，不是 sync_outputs_to_docmgr (2026-06-22, bug-009):** AI 在对话里生成的文档要进「我的文档」个人文件夹，靠的是前端 `chat-box.tsx` 在 AI 回复结束时 POST `/docmgr/sync-thread-files` → `AIDocumentService.sync_thread_files`（service.py:318）。代码里另有一套 `sync_outputs_to_docmgr`+`_ensure_subfolder`（会建子文件夹+设 folder_id）看起来像正规实现，但它是**死代码**——`register_present_files_callback` 在 app 层零调用，`present_file_tool.py` 连 `_try_fire_sync_callback` 都不引用了。诊断「文档不显示」的第一刀：查 `ai_documents.folder_id` 是否 NULL——文件夹树 `get_folder_tree` 和 `/documents?folder_id=` 全按 folder_id 归档，NULL=无家可归=不显示。本次根因：`sync_thread_files` 和 `create` 都只写 `folder=<标题>` 字符串、从不设 folder_id；且 6 个活跃用户只有 admin/lisi 有「我的文档」根文件夹（06-09 手工 seed，无 seed 代码）。修法：`_ensure_subfolder` personal 分支自动 find-or-create 根文件夹，两处创建点都写 folder_id。**别被 admin 这个表象带偏——对所有用户都坏，不是权限/角色问题。**
- **get_db_context 用法 (2026-06-22):** `get_db_context()` 是 async context manager，正确用法 `async with get_db_context() as db:`（见 dictionary_loader/pipeline/template_tools）。`sync_outputs_to_docmgr` 里写的 `async for db in get_db_context():` 是**潜在 bug**——只因为它是死代码从没跑过才没炸。新代码别照抄那个 async for。
- **删除前必须当场复检目标状态 (2026-06-22, Do-Not-Repeat):** 清理「空文件夹/孤儿文档」时，调研和真正 DELETE 之间若有活的写入进程（gateway 在跑、sync 在跑），目标状态会变。本次：一个 backfill 时 0 文档的「空」子文件夹，删前复检发现已被一次新同步（16:43，修复上线后）填入 6 条 ch_0x.md——若照原计划删了会 SET NULL 这 6 条新文档。**铁律：DELETE 前当场 SELECT 一次 count/内容，不要信任几分钟前的调研快照。** 同一次清理里还印证：bug-009 修复在生产已生效（那次 16:43 的同步正确归档了 6 文档到线程子文件夹）。
- **folders 删除的级联 (2026-06-22):** `folders` 被 `folders.parent_id`(CASCADE) 和 `ai_documents.folder_id`(SET NULL) 引用。即删一个文件夹：子文件夹跟着级联删，但里面的文档只会被 SET NULL（变 homeless），不会删。所以删"空"文件夹前要确认 0 文档引用，否则会把文档打成 homeless。

- **Tailwind v4 color-token override for scoped theming (2026-06-22, sci-fi page):** Tailwind v4 emits color utilities as `color: var(--color-blue-400)` (real CSS vars from `@theme`). To make a self-contained themed component (e.g. `.cyber-root`) flip accent colors per app theme WITHOUT editing every class, re-define the tokens under a scoped selector: `.light .cyber-root { --color-blue-400: #2563eb; --color-purple-400: #9333ea; … }`. Every `text-blue-400`/`text-purple-400` inside that subtree then resolves to the darkened shade automatically. `.light .cyber-root` (specificity 0,2,0) beats the `:root` theme definition (0,1,0). Verified live: `getComputedStyle(el).color` on `text-blue-400` flips `#60a5fa`→`#2563eb`. Safe because the `-400` shades were used only for text/icons (2 subtle `/20` borders). The eai-flow app's theme is controlled by next-themes via `基础设置` (settings/basic-settings.tsx → `setTheme()`), which sets `.light`/`.dark` on `<html>` — so any `.light .X` / `.dark .X` CSS reacts to the same switch. `@custom-variant dark (&:is(.dark *))` is at globals.css:133.

- [2026-05-28] Chose BlockNote over Tiptap for the collab editor. BlockNote v0.51 provides native Yjs collaboration support (fragment + provider + user + showCursorLabels), Notion-style block editing, and built-in markdown import/export (blocksToMarkdownLossy, tryParseMarkdownToBlocks). - **Collab seeding flow:** When a document is first opened in the BlockNote collab editor, the Hocuspocus server's `onLoadDocument` loads from `collab_documents.yjs_doc`. - **ExportDocxDialog integration gap:** When creating new dialog components, always complete the full integration chain: (1) create the component, (2) import it in the parent, (3) add state to control open/close, (4) wire the trigger to set state, (5) render the component in JSX. - **python-docx CJK font fix:** `run.font.name` only sets Latin/ASCII fonts (`w:ascii`/`w:hAnsi`). For Chinese text to render correctly, must also set `w:eastAsia` attribute on `<w:rFonts>` element. Use a helper like `_set_run_font(run, font_name)` that sets both. Keep the Chinese name (e.g. "宋体") for `w:eastAsia` and the English name (e.g. "SimSun") for `w:ascii`.
