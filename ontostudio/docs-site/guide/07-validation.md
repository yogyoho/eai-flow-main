# 07 校验中心

> 对齐：`frontend/src/pages/ValidationPage.tsx` @ 2026-10-06

## 入口

侧边栏「建模层 → 校验中心」。全图体检站：SHACL 形状校验 + 国标 GB/T 48000.3 符合性套件（C1-C5）+ 数据治理，每次全量装载/推理后可重跑。

## 核心操作

- **▶ 重新校验**：唯一触发方式。校验是重操作（全图 pyshacl 约 20 秒，2026-10-04 定案不自动跑），结果进校验历史
- **校验历史面板**：每次重校自动记录，回看趋势
- **数据治理面板**：两类专项清理——**内核孤儿实体**（asserted 图有、dg_* 表无）扫描→确认→精确清除；**零边 mention**（证据不指向任何实体/关系，SHACL sh:or 违规的根因）治理
- **导出报告 JSON**：校验结果落文件，供评审留档

## 结果解读

- **SHACL 分区**：违规行带 focusNode 可跳 [03 实体库](./03-entities) 定位；severity 分级处理（Violation 该修 / Warning 批量审 / Info 挂着）——报告五要素怎么读见 [SHACL 概念页](../concepts/shacl)
- **国标五项**：C1-C5 逐项状态，条款对照与诚实边界见 [GB/T 48000.3 符合性](../reference/gbt-48000)
- **「范围：全域」按钮是灰的**：按域过滤为规划项（单域阶段全域够用），多域化后接真——不是坏了

## 常见问题

- **校验服务不可达/未登录提示**：后端不可达或会话过期，先确认 ontostudio-backend 在跑
- **校验完国标五项全绿但 SHACL 有违规**：正常——五项校验的是"机制合规"（IRI 规约/序列化/报告形态/元数据/扩展），SHACL 违规是"数据质量"，两回事
- **刚清完治理孤儿又出现**：上游（抽取→确认）还在产同样的脏数据，治本去 [审阅闭环](./review-loop) 收紧确认标准
