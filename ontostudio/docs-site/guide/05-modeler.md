# 05 本体建模器

> 对齐：`frontend/src/pages/ModelerPage.tsx` @ 2026-10-06

## 入口

侧边栏「建模层 → 本体建模器」。registry（"字典+语法书"，见[本体地基](../concepts/foundations)）的编辑器：三栏布局 = 域文件列表 | 编辑器单面板 | 右栏 300px。

## 双编辑模式

| 模式 | 能做什么 |
|---|---|
| **可视化** | TBox 画布：真实类层次 + 实例计数 + 属性链。节点可拖拽移位（纯视图态，不落 YAML，切域重置）；「＋子类」进入连线模式——点选父类完成 `subClassOf` 加边；表单父类 chips 增删=边编辑；新建类（草稿追加，画布居中出现） |
| **YAML 源码** | 行号编辑器直改——结构编辑的兜底，schema 校验兜底 |

## 编辑管线（关键纪律）

**表单 / 画布 / YAML 三处编辑都落在同一份 `draftText`（单一草稿）** → 校验 → 保存。

- 保存走 **fingerprint 乐观并发**：别人先保存了你再保存会冲突（409），刷新合并后再试
- 保存成功 = `registry_version` 递增 + SHA 热重载——图谱浏览、总览的 registry 指纹随之更新
- 保存前想验草稿：校验中心的「注册表草稿校验」通道（validate 端点）

## 结果解读

- 画布节点上的实例计数是当前域真实数据量——计数为 0 的类是"有模型无数据"，去抽取导入灌数
- 加边失败先看父类是否已声明（C4 国标项：subClassOf 目标必须已声明）

## 常见问题

- **拖拽位置重启后没了**：拖拽是视图态，registry 无布局数据——按设计如此
- **保存报 409**：乐观并发保护，拉最新草稿合并你的改动再保存
- **改了类名图谱里的旧实例去哪了**：实例按 etype 挂在类下，改名是新建类不是重命名——先想清数据迁移，再动 schema
