# owlrl 闭包

> 对齐：`ontology_reason`（ontology MCP）+ reasoning 推理页 @ 2026-10-06

## 一句话类比

闭包（closure）= **把"隐含的句子"全部推出来摆上台面**——词典说"矸石山是一种工业固废"（子类），台账里有一条"煤矸石山 1 号"（实例），那么"煤矸石山 1 号是工业固废"不用任何人写，闭包之后图里就有它。

## 在 OntoStudio 里对应什么

**OWL 2 RL 规则子集**：OWL 推理的"工程版"——把完整的描述逻辑压成一条条 if-then 规则，牺牲理论完备性换工程可用性。owlrl 是这个规则集的标准实现。本系统用它做**标准规则推理**。

**执行流**（`ontology_reason` 工具 / 推理工作台「infer」）：

```
schema 重编 → owlrl 闭包计算 → 物化三元组落 graph:entailment 命名图
```

- 物化（materialization）= 把推出来的三元组真实写进图（不重算就能查）
- 落点在独立命名图 `graph:entailment`，与断言图（人写进去的）严格隔离——推理结果不冒充人工事实
- 返回输入三元组数 / 物化三元组数 / 各规则派生计数
- **置信度门默认 0.7**：低于阈值的候选不参与推理（`min_confidence` 参数可调）

## 你在哪能看到/操作它

- **06 推理工作台**：点 infer 跑闭包，看"物化 N 三元组"与分规则计数
- **ontology MCP 的 `ontology_reason` 工具**：Agent 侧同一能力的入口（[MCP 工具总表](../reference/mcp-tools)）

## 常见坑

- **prp-spo2 静默零推断（真实踩坑，buglog 在案）**：属性链类规则（如"传递链"）在**链首没有实例**时，owlrl 不报错、不告警、安静地返回零推断。golden 夹具只测"有数据时推得对"，测不出"没数据时该提醒没提醒"。排查口诀：**推理结果为空，先查链首类型在图上有没有实例**，再怀疑规则写错。
- **物化数 ≠ 新知识数**："1857 物化"是闭包总规模（大量是平凡的 rdfs:subClassOf 传递），有价值的派生结论是其中一小部分。别拿物化数当 KPI。
- **闭包会过时**：断言图变了，旧闭包就是陈旧的——重要变更后重跑 infer，校验中心的状态卡也会提示。
