# TriG 快照

> 对齐：kernel export（TriG 快照）+ G1 每日调度 @ 2026-10-06

## 一句话类比

**TriG** = 带"抽屉"的 Turtle——一个文件里装多个命名图，每个抽屉独立开合。**快照** = 给整个图库拍时点存档：今天图长什么样，原封不动存一份，30 天内随时可回看。

## 在 OntoStudio 里对应什么

**TriG 格式**：Turtle 的超集（语法兼容，见 [Turtle 与 JSON-LD 1.1](./turtle-jsonld)），多了命名图标记：

```trig
<http://ontostudio.example/graph/asserted> {
    dg:e123 dg:label "西山遗址" .
}
<http://ontostudio.example/graph/entailment> {
    dg:e123 dg:etype "sensitive_point" .
}
```

图上的"抽屉"与推理分层一一对应：断言图（人审过的）/ `graph:entailment`（owlrl 闭包）/ `graph:derived:*`（CONSTRUCT 派生）——一个 TriG 快照把所有抽屉连同标签一起存下来，图边界不丢。

**快照调度（G1）**：

- 每日 06:00 自动拍全量 TriG 快照，可恢复调度器驱动
- **30 天滚动清理**：30 天前的快照自动删除
- 手动快照/恢复之外，另有「从主系统线程导入」（`formal/load`）全量装载通道——那是"灌数据"，不是"回时点"

## 你在哪能看到/操作它

- **09 导出互操作 → 快照历史卡**：看已有快照清单（调度产出的自动快照也在列）、手动触发、恢复
- Agent/集成侧：快照文件即图库的完整时点表示，可直接被 pyoxigraph 装载

## 常见坑

- **快照 ≠ 备份恢复的替代**：恢复走的是装载语义（快照内容重灌），不是数据库级 point-in-time restore——恢复前确认当前图的处理方式（覆盖还是并存）。
- **30 天外不留**：滚动清理到点即删，重要时点（如评审基线）要**手工另存**到图库之外。
- **抽屉标签是语义的一部分**：手工处理 TriG 时别把命名图标记剥掉只留三元组——断言和推理产物混回一个图，等于把"人审过的"和"机器推的"搅在一起。
