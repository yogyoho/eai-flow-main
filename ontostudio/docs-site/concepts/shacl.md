# SHACL

> 对齐：校验中心 pyshacl 集成 + C3 报告形态校验 @ 2026-10-06

## 一句话类比

SHACL 是**图上的质检规则清单**——"每个实体必须有名称""零边证据不合格"，不合规矩的节点被揪出来出报告。它管的是"数据长没长成规定的形状"（Shapes = 形状），不推导新事实。

## 在 OntoStudio 里对应什么

**形状（shape）**：一条质检规则，声明某类节点应满足的约束——必填属性、取值范围、指向关系。规则本身也是三元组，和图存在一起。

**校验报告五要素**：每条违规是一份结构化记录——

| 要素 | 含义 | 例子 |
|---|---|---|
| `focusNode` | 哪个节点违规 | 西山遗址（实体 IRI） |
| `path` | 哪条属性出的问题 | `dg:label` |
| `message` | 人读的违规说明 | "实体缺少中文名称" |
| `severity` | 严重度 | Violation / Warning / Info |
| `source` | 哪条形状规则触发 | 规则 IRI |

国标符合性 **C3** 校验的正是"报告五要素齐不齐"——报告必须结构化可机读（[GB/T 48000.3 符合性](../reference/gbt-48000#c3--条款-53--shacl-报告)）。

**pyshacl**：本系统的 SHACL 校验引擎（Python 实现）。全图校验约 20 秒——属重操作，只由「07 校验中心 → ▶ 重新校验」按钮触发（2026-10-04 定案，不做后台常跑），每次校验自动进校验历史。

## 你在哪能看到/操作它

- **07 校验中心**：SHACL 违规分区 + 国标五项；每行违规可跳「03 实体库」定位节点；可导出报告 JSON
- **数据治理面板**（校验中心内）：SHACL 违规的高发惯犯——内核孤儿实体（asserted 有、dg_* 表无）与零边 mention（证据不指向任何实体/关系）在这里确认清除
- **05 本体建模器**：保存 registry 前的草稿校验走同一套 shapes 的 schema 侧

## 常见坑

- **SHACL ≠ 推理**：它只判断"现有数据合不合形状"，不产生新三元组。要"推出隐含事实"是 [owlrl 闭包](./owlrl) 和 [CONSTRUCT 派生](./sparql-construct) 的事。三者常被混为一谈。
- **报告完整 ≠ 图干净**：C3 过了只说明报告格式合规；违规清单长不长是数据质量，去治理面板清。
- **severity 分级是流程信号**：Violation 该修，Warning 可批量审，Info 常年挂着也正常——别按同一个节奏处理。
