## 五项校验详解

### C1 · 条款 5.4 · IRI 命名规约

- **校什么**：每个域的命名空间必须是合法 http(s) 形态；每个实例 IRI 必须形如 `命名空间 + id/<uuid>`，从 IRI 机械可逆地解出域与 id。
- **在哪跑**：校验中心「重新校验」；代码入口 `kernel/conformance.py`。
- **通过标准**：全部 IRI 匹配规约，无自由拼接的裸标识。
- **已知局限**：无。

### C2 · 条款 5.3 · 序列化往返

- **校什么**：schema 图以 Turtle 序列化后再装载，与原图同构；store 装载前后一致。
- **在哪跑**：校验中心；与「09 导出互操作」页的 Turtle / JSON-LD 导出同源——导出格式即往返校验的载体（深读：[Turtle 与 JSON-LD 1.1](../concepts/turtle-jsonld)）。
- **通过标准**：往返无三元组增删。
- **已知局限**：无。

### C3 · 条款 5.3 · SHACL 报告

- **校什么**：SHACL 校验结果必须是结构化报告，且五要素齐备——focusNode / path / message / severity / source。
- **在哪跑**：校验中心（SHACL 分区，违规行可跳实体库定位）。深读：[SHACL](../concepts/shacl)。
- **通过标准**：报告形态完整可机读。
- **已知局限**：报告完整 ≠ 图无违规——违规清单是数据质量面，在数据治理面板处理（内核孤儿实体 / 零边 mention）。

### C4 · 附录 A · 元数据八项

- **校什么**：类声明与标签齐备；`subClassOf` 的目标类必须已声明（不许悬空引用）。
- **在哪跑**：校验中心。
- **通过标准**：八项元数据全满。
- **已知局限**：无。

### C5 · 条款 9 · 扩展原则

- **校什么**：每个域命名空间唯一且非 W3C 保留字；类名合法（扩展不污染标准词表）。
- **在哪跑**：校验中心。
- **通过标准**：零保留字冲突、零跨域命名空间重用。
- **已知局限**：无。

## 边界与规划（诚实声明）

- **形式化能力当前为空**：无 OWL 公理级建模，国标对形式化的要求未覆盖——这是"未做"，不是"满足"。
- **跨域四链路数据未补齐**：3×NO_DATA + 1×匹配率 0.0%，本体平台宣称的跨域能力当前是死链；启用前置=匹配率达标或人工入库补链（主系统 TODOS 在册）。
- **按域校验未接真**：校验中心「范围：全域」按钮为规划项；单域阶段全域校验够用，多域化落地后按域过滤成为排查刚需。
